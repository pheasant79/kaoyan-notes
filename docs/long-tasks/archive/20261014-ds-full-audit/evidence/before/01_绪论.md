# 第1章 绪论

> **本章要解决的问题：** 怎样描述数据、规定操作、选择表示方式，并评价算法代价？

<span style="color:#2563EB"><strong>一句话主线：</strong></span>
数据元素 → 数据之间的关系 → 抽象操作规范 → 具体存储实现 → 算法与复杂度。

[返回全书总览](00_全书总览.md)

## 先看结论

- <span style="color:#2563EB"><strong>必须掌握：</strong></span>数据结构描述的是“数据元素 + 元素之间的关系”，不是某一种代码写法。
- <span style="color:#2563EB"><strong>必须掌握：</strong></span>逻辑结构回答“数据之间怎样组织”，存储结构回答“这种关系怎样在计算机中表示”。
- <span style="color:#2563EB"><strong>必须掌握：</strong></span>ADT 规定数据对象、关系和操作的效果，但不规定数组、指针等具体实现。
- <span style="color:#DC2626"><strong>必须掌握：</strong></span>时间复杂度、空间复杂度、最好/平均/最坏情况和 O/Ω/Θ 不是同一组概念。

## 知识主线

数据结构的分析顺序可以固定为：

1. **对象：** 要处理哪些数据元素？
2. **关系：** 元素之间是集合、线性、树形还是图状关系？
3. **规范：** 允许做哪些操作，操作的结果是什么？
4. **实现：** 用连续空间、链接、索引还是散列表示？
5. **算法：** 在这种表示上如何完成操作？
6. **评价：** 算法是否正确，时间和空间代价多大？

## 知识展开

<a id="data-levels"></a>
## 数据的基本单位

- **数据项：** 构成数据元素的属性，在当前抽象层次上通常不可再分。
- **数据元素：** 通常作为一个整体处理的基本单位。
- **数据对象：** 具有相同性质的数据元素集合。
- **数据结构：** 相互之间存在特定关系的数据元素集合。
- **数据类型：** 一个值的集合，以及定义在这些值上的操作集合。

**短例子：** 学生记录可以看作一个数据元素；学号、姓名是数据项；所有学生记录组成数据对象。

<a id="data-structure-type"></a>
## 数据结构与数据类型

数据类型偏重“有哪些值、允许做什么操作”；数据结构进一步强调“多个数据元素之间有什么关系，以及怎样组织这些关系”。

因此，`int` 是数据类型；线性表、树和图是数据结构。二者不是完全同义的术语。

<a id="logical-structure"></a>
## 逻辑结构

逻辑结构只描述元素之间的关系，不预设元素在内存中的位置。

- **集合：** 除了同属一个集合，不规定其他关系。
- **线性结构：** 元素之间形成一对一的前后关系。
- **树形结构：** 元素之间形成一对多的层次关系。
- **图状结构：** 元素之间可以形成一般的多对多关系。

<span style="color:#DC2626"><strong>易错：</strong></span>
“线性表”是逻辑结构；“顺序表”是它的一种存储实现。逻辑结构和存储结构不能当作同义词。

<a id="storage-structure"></a>
## 存储结构

存储结构是在计算机中表示数据元素及其关系的方式。

### 顺序存储

用连续存储单元和位置规则表示逻辑关系。

- 优点：按位置计算地址，访问方便。
- 代价：插入、删除可能需要移动一段元素；扩容可能搬迁数据。

### 链式存储

用结点保存数据，并用链接记录逻辑上的前后关系。

- 优点：不要求结点物理相邻，调整链接较灵活。
- 代价：需要额外链接空间；按位访问通常要沿链接寻找。

### 索引存储

在数据记录之外建立“关键字或范围信息 → 位置”的索引。

- 优点：可以缩小搜索范围。
- 代价：索引占空间，还要随着数据变化维护。

### 散列存储

通过散列函数把关键字映射到表内槽位或桶，再处理冲突。

- 优点：等值定位在条件合适时很快。
- 代价：性能受散列函数、装填因子和冲突处理影响。

<a id="adt"></a>
## 抽象数据类型 ADT

ADT 是对数据对象、逻辑关系和操作效果的抽象规范。

它说明：

- 有哪些数据对象；
- 对象之间具有什么逻辑关系；
- 可以执行哪些操作；
- 每个操作的输入、输出和效果是什么。

它不规定：

- 数据必须放在数组还是链表中；
- 结点链接用指针还是游标表示；
- 具体算法必须采用哪种代码写法。

<span style="color:#8B5CF6"><strong>关联：</strong></span>
第2章的线性表、第3章的栈和队列，都是先规定抽象操作，再分别讨论顺序或链式实现。

## 数据运算与算法

- **数据运算：** 访问、插入、删除、查找、遍历等，回答“要做什么”。
- **算法：** 为解决问题而设计的有限步骤，回答“怎样完成”。

算法的基本特征：

1. **有穷性：** 在有限步骤后结束。
2. **确定性：** 每一步含义明确，同样输入不会产生含糊执行。
3. **可行性：** 每一步都能由已有基本操作实现。
4. **输入：** 可以有零个或多个输入。
5. **输出：** 至少产生一个结果。

算法还应关注正确性、可读性、健壮性和效率。

<a id="complexity"></a>
## 复杂度

### 时间复杂度

描述基本操作次数随输入规模增长的数量级。分析时要先说明规模 `n` 和具体输入情况。

- 顺序执行通常保留增长最快的主导项；
- 循环要看循环变量怎样变化；
- 嵌套循环不一定就是 `O(n²)`；
- 递归要结合递推关系或调用深度分析。

### 空间复杂度

本知识库默认采用**辅助空间**口径：不把输入本身占用的空间算作额外空间，但要计入递归栈和临时数组。

### 最好、平均、最坏情况

它们描述同一规模下不同输入造成的运行情况：

- 最好情况：最有利输入；
- 平均情况：按输入分布取平均；
- 最坏情况：最不利输入。

<a id="asymptotic"></a>
## 渐进记号

- `O(g(n))`：渐进上界，增长不超过某个数量级。
- `Ω(g(n))`：渐进下界，增长至少达到某个数量级。
- `Θ(g(n))`：紧确界，上下界同阶。

<span style="color:#DC2626"><strong>注意：</strong></span>
“O”与“最坏情况”属于不同维度。一个算法可以讨论最好情况的 `O(n)`，也可以讨论最坏情况的 `O(n²)`；不能把 `O` 直接翻译成“最坏”。

常见增长阶：

`O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2^n)`

<a id="boundaries"></a>
## 易错与边界

- ADT 是功能规范，存储结构是表示方式，算法是实现步骤。
- 一种逻辑结构可以有多种存储实现；一种存储方式也可服务多种逻辑结构。
- 顺序、链式、索引、散列不是四个绝对互斥的盒子，实际系统可以组合使用。
- `struct`、`typedef`、指针和动态分配是语言或实现工具，不是新的逻辑结构。
