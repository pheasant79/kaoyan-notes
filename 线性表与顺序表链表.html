线性表与 C/C++ 实现纠偏教程

把教材里的抽象数据类型、C 语言模板、C++ 引用、顺序表和单链表一次拆开。

1 数据结构、数据类型、线性表的关系

你现在的理解

数据结构像是“所有存储的集合”，里面有很多类；int、float 也像一种数据结构。

正确模型

int、float 通常叫数据类型，不是教材意义上的数据结构。数据结构研究的是：一组数据元素之间有什么关系，以及这些关系如何存储和操作。

一句话结论数据类型回答“这个值是什么”；数据结构回答“一批值如何组织”。线性表是数据结构，不是 C 语言专属语法。

2 InitList 这类基本操作是谁定义的？

你现在的疑惑

我写了三年代码没见过 InitList，所以它是不是只在 C 语言课程里讲，实际很少用？

正确模型

InitList、ListInsert、ListDelete 不是 C 语言内置函数，也不是所有语言必须叫这个名字。它们是教材为了描述“线性表这个抽象对象应该支持哪些操作”而起的标准化名字。

教材名字真实工程里可能叫什么本质
InitListnew ArrayList()、[]、vector<int> v创建空表
ListInsertpush_back、insert、append插入元素
ListDeleteerase、remove、pop删除元素
GetElema[i]、get(i)、at(i)按位置取元素
// C 教材写法：函数名显式写出来 InitList(L); ListInsert(L, 3, x); // C++/Python/JavaScript 常见写法：库和语法帮你封装了 vector<int> v; v.push_back(x); arr.append(x); // Python list.push(x); // JavaScript
一句话结论你不是没用过线性表操作，只是没用过教材给它起的中文/C 风格名字。

3 线性表是抽象的，为什么还能有操作？

你现在的理解

线性表只是逻辑结构，真正有函数的应该是顺序表、链表这种具体对象。

正确模型

你这句话有一半非常对：线性表确实是抽象逻辑结构。但“抽象对象”也可以规定操作，只是这些操作不规定底层怎么实现。

一句话结论线性表定义“能干什么”，顺序表/链表定义“怎么干”。

4 顺序表和数组的关系

你现在的疑惑

顺序表很像数组，它到底就是数组吗？

正确模型

顺序表通常用数组实现，但不等于裸数组。顺序表 = 数组存储空间 + 当前长度 + 容量限制 + 一组操作规则。

typedef struct { int data[100]; // 存储空间：数组 int length; // 当前有几个元素 } SqList;
对象有什么缺什么
裸数组 int a[100]连续空间不知道当前用了几个；没有统一插入删除规则
顺序表 SqList连续空间 + 当前长度 + 操作本质仍依赖数组作为底层存储
一句话结论顺序表不是“数组这个语法”，而是“用数组实现的线性表”。

5 静态分配、动态分配、动态数组

你现在的理解

静态分配是创建数组；动态数组像是创建一个指针，然后通过指针实现伪数组。

正确模型

动态分配不是“伪数组”。它仍然是一块真实连续内存，只是这块内存不是写死在结构体里，而是在运行时向堆区申请，然后用指针保存首地址。

// 静态分配：数组大小写死 typedef struct { int data[100]; int length; } StaticList; // 动态分配：运行时申请连续空间 typedef struct { int *data; // 指向一块连续内存的首地址 int length; int capacity; } DynamicList;
方式空间在哪能不能扩容数组下标能用吗
静态分配结构体内部固定数组不方便能
动态分配堆区连续内存，结构体里存首地址可以重新申请更大空间能，data[i] 本质是地址偏移
一句话结论int *data 不是伪数组，它是“指向连续数组空间的入口”。

6 C 的 & 与 C++ 引用 &

你现在的疑惑

C 里 & 是取地址；C++ 里评论说它是引用，不是指针。它是不是只是把传地址改了名字？

正确模型

符号一样，语境不同。表达式里的 &x 是取地址；声明里的 int &r = x 是 C++ 引用。引用在语义上是变量的别名，底层实现常常类似地址，但语言规则和指针不一样。

写法语言/语境含义调用处
f(&x)C / C++ 表达式把 x 的地址传过去能看见 &
void f(int *p)C / C++ 参数声明p 是指针变量函数里用 *p
void f(int &r)C++ 参数声明r 是实参的别名调用写 f(x)，不用 &
// C：指针传参 void setZero(int *p) { *p = 0; } setZero(&x); // C++：引用传参 void setZero(int &r) { r = 0; } setZero(x);
一句话结论C++ 引用经常“像传地址一样实现”，但它在语言层面是别名，不是可随便改指向的指针变量。

7 单链表、LNode、LinkList 到底是什么？

你现在的疑惑

LinkList 看起来像系统给的东西；typedef struct LNode *LinkList; 到底是把谁重命名成谁？

正确模型

LinkList 完全不是系统定义的。它只是用户用 typedef 起的别名，意思是：以后把 struct LNode * 这种指针类型叫做 LinkList。

typedef struct LNode { int data; struct LNode *next; } LNode, *LinkList;
片段含义
struct LNode结构体类型的正式名字，递归定义 next 时必须用它
LNodestruct LNode 的别名，表示“一个节点结构体”
LinkListstruct LNode * 的别名，表示“指向节点的指针”
LNode *p声明一个节点指针
LinkList p同样声明一个节点指针
// 这两句等价 LNode *p; LinkList p; // 注意：LinkList 已经包含了星号 LinkList L; // 对：L 是 LNode* *LinkList L; // 错：不能这么写
一句话结论LinkList 不是“链表系统类型”，只是 LNode * 的别名；教材用它是为了让代码读起来像“一个链表”。

8 LNode *p = L->next 到底发生了什么？

你现在的疑惑

LNode *p = L->next; 怎么会让一个结构体等于结构体内的具体 next 呢？是不是自动让 *p 里的 next 等于 next？

正确模型

这里没有“结构体等于结构体”。p 是一个指针变量，L->next 也是一个指针值。这句话只是把一个地址复制给另一个指针变量。

LNode *p = L->next; // 等价于更慢的拆法： LNode *p; p = L->next; // L->next 等价于： (*L).next

结构体为什么不能直接 ==？

C 语言允许结构体整体赋值，但不允许直接用 == 比较两个结构体。原因不是“地址不能比较”；指针地址其实可以比较是否相等。真正原因是：C 标准没有为结构体自动定义“相等”的规则。

写法是否允许原因
a = b;允许按成员整体复制结构体内容
a == b;不允许结构体可能有填充字节、数组成员、浮点 NaN 等问题，C 不自动决定比较规则
&a == &b;允许比较两个结构体变量是不是同一个地址
a.id == b.id && ...允许你自己逐字段定义“相等”
一句话结论LNode *p = L->next; 是“指针变量接收一个地址”，不是“结构体接收结构体”。结构体比较要自己定义规则，不能指望 C 自动知道你想比什么。
