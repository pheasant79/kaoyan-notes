# 第3章 栈、队列和数组

> **本章要解决的问题：** 限制操作位置会产生什么结构和用途？多维下标怎样映射到线性存储？

<span style="color:#2563EB"><strong>一句话主线：</strong></span>
受限线性表（栈、队列）与下标组织结构（数组、矩阵）是两条并列分支，不要强行写成先后演变。

[返回全书总览](00_全书总览.md)

## 先看结论

- <span style="color:#2563EB"><strong>必须掌握：</strong></span>栈是 LIFO，队列是 FIFO；二者的区别来自操作约束，不是存储方式。
- <span style="color:#DC2626"><strong>必须掌握：</strong></span>循环队列的判空、判满公式依赖具体约定，不能脱离 `front/rear` 定义背公式。
- <span style="color:#2563EB"><strong>必须掌握：</strong></span>数组解决的是按下标定位问题；数组既可实现顺序表、栈、堆，也可表示邻接矩阵。
- <span style="color:#16A34A"><strong>必须掌握：</strong></span>栈常用于括号匹配、表达式和递归；队列常用于等待服务和 BFS；DFS 使用栈或递归。

## 知识主线

本章分成两个并列方向：

- **操作受限：** 栈 → 队列 → 应用。
- **下标定位：** 数组 → 地址映射 → 特殊矩阵与稀疏矩阵压缩。

<a id="stack"></a>
## 栈

栈只允许在同一端进行插入和删除：

- 插入称为**入栈**；
- 删除称为**出栈**；
- 访问删除端元素称为**读栈顶**；
- 次序是**后进先出（LIFO）**。

### 栈的实现

- **顺序栈：** 数组保存元素，用栈顶位置记录当前范围；需要处理容量边界。
- **共享栈：** 两个顺序栈共用一个数组，从数组两端向中间增长。
- **链栈：** 通常在链表头部入栈和出栈，避免每次寻找链尾。

### 栈的典型用途

- **括号匹配：** 左括号入栈；遇右括号时与栈顶匹配；结束时栈必须为空。
- **表达式处理：** 栈保存运算符或操作数，根据优先级和结合方向处理。
- **递归执行：** 调用栈保存返回位置、参数和局部状态；递归必须有终止条件。

<span style="color:#16A34A"><strong>方法：</strong></span>
把“最近遇到但尚未完成”的对象放进栈，正是 LIFO 适合处理嵌套关系的原因。

<a id="queue"></a>
## 队列

普通队列在一端插入、另一端删除：

- 队尾入队；
- 队头出队；
- 次序是**先进先出（FIFO）**。

### 队列的实现

- **顺序队列：** 用数组保存元素。
- **链队列：** 通常同时维护队头和队尾，使入队、出队不必扫描全表。
- **循环队列：** 让下标按容量取模，复用已经出队的前部空间。

<a id="circular-queue"></a>
## 循环队列

以下采用“容量为 `N`、保留一个空位”的常见约定：

- `front` 指向队头元素；
- `rear` 指向下一个可入队位置；
- 队空：`front == rear`；
- 队满：`(rear + 1) mod N == front`；
- 元素个数：`(rear - front + N) mod N`；
- 实际最多存放 `N-1` 个元素。

**短例子：** 队列出队后，前部出现空位。普通顺序队列的 `rear` 若只向后移动，可能报告“溢出”；循环队列让 `rear` 绕回前部，这种现象就是避免假溢出。

<span style="color:#DC2626"><strong>注意：</strong></span>
如果实现改用“计数器”或“标志位”区分队空和队满，就不能继续套用“留一个空位”的判定式。

<a id="array-mapping"></a>
## 数组地址映射

数组按一组下标定位元素。多维数组在内存中通常仍要线性排列，因此需要把多维下标换算成偏移量。

设二维数组有 `r` 行、`c` 列，元素宽度为 `w`，首地址为 `B`，下标从 0 开始：

- **行优先：** `A[i][j]` 地址为 `B + (i × c + j) × w`。
- **列优先：** `A[i][j]` 地址为 `B + (j × r + i) × w`。

<span style="color:#DC2626"><strong>易错：</strong></span>
公式必须和“下标起点、行列数、存储顺序”同时确认，不能只记形式。

<a id="matrix-compression"></a>
## 矩阵压缩存储

### 特殊矩阵

利用元素分布规律减少存储：

- 对称矩阵：只存上三角或下三角；
- 三角矩阵：只存一个三角区，另一侧可能是公共常量；
- 带状矩阵：只保存主带及附近元素，例如三对角矩阵。

压缩后，访问元素需要先判断它属于哪一部分，再按规则换算一维位置。

### 稀疏矩阵

当非零元素数量 `t` 远小于总元素数时，只存非零值及其行列位置，例如三元组表。

- 空间通常随 `t` 增长，而不是随完整矩阵规模增长；
- 代价是访问不再能直接套用完整数组地址公式；
- 若运算要求频繁随机访问，压缩表示未必总是更方便。

对称 `n` 阶矩阵的独立元素数量为 `n(n+1)/2`。

## 性质与代价

- 常规栈、队列的一次入/出操作通常为 `O(1)`，不含扩容等额外开销。
- 长度为 `n` 的括号匹配：时间 `O(n)`，最坏辅助空间 `O(n)`。
- 递归辅助空间取决于最大调用深度，而不是函数代码有多少行。
- 稀疏矩阵三元组空间通常为 `O(t)`，`t` 为非零元个数。

<a id="boundaries"></a>
## 易错与边界

- 顺序/链式是**存储实现维度**；LIFO/FIFO/双端是**操作约束维度**。
- 循环队列不是循环链表；二者“循环”的对象、目的和实现方式不同。
- 双端队列允许两端操作，不应直接等同于普通 FIFO 队列。
- 数组下标有序不代表元素值有序。
- 共享栈属于顺序栈的空间组织方式；二叉堆是第8章的堆序结构，不是本章的普通栈。
