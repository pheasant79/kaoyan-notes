# 《数据结构》全书逐章诊断与拟定知识树

> 本稿是正式重写前的审查稿，不是最终章节正文。  
> 作用：先确认每章“研究什么、知识点放在哪里、哪些内容必须补、哪些内容只作关联”，避免先排版后返工。

## 一、全书总判断

### 已经成立的部分

- 八章范围清楚，符合常见 408 数据结构主干：绪论、线性表、栈队列数组、串、树与二叉树、图、查找、排序。
- 第二章样张已经建立了可推广基准：先用知识树定位，再用结构图/过程图解释，最后给条件、代价和边界。
- 颜色语义、Markdown + 少量 HTML、重要方法才用比较表的规则可以保留。
- 当前章节普遍没有把完整 C/C++ 代码塞进正文，这是正确的；实现语言只在帮助理解时出现。

### 目前不能直接推广的部分

- 第1、3至8章仍以连续文字为主，知识树和图解不足；读者能看到术语，却不总能看到“这个术语属于哪个问题分支”。
- 有些章节把“结构、实现、算法、评价指标、应用”并排放在同一层，层级虽有标题，主线仍不够可视化。
- 复杂度大多正确，但部分结论需要绑定实现、输入条件或图存储方式，不能只写一个裸 `O(...)`。
- 第5章的树/森林与二叉树转换在现有正文中缺失；第7章散列冲突处理过于概括；第8章外部排序和非比较排序需要更清楚的条件边界。
- 全书总览目前更像索引页，下一版需要保留索引功能，同时增加“概念归属树”和跨章复用关系。

### 全书统一主线

```text
数据对象
→ 逻辑关系
→ 存储表示
→ 基本操作
→ 针对问题的算法
→ 前提、代价与适用边界
```

跨章节复用关系：

```text
第1章提供分析语言
→ 第2～6章提供结构与基本算法
→ 第7章用结构组织记录并定位
```

## 二、逐章审查

## 第1章 绪论

### 当前评价

- **结构：基本正确，但偏“定义列表”。** 现有顺序是数据层次→逻辑结构→存储结构→ADT→算法→复杂度，方向正确；缺少一张把这些层次串起来的总图。
- **内容：主干基本够，但边界还可以更严。** 数据类型与数据结构、数据运算与算法、复杂度与最好/平均/最坏已提到，但需要用同一例子说明它们不是同一层概念。
- **适合图解：很适合做全书概念坐标图，不需要做代码图。**

### 必须保留

- 数据项、数据元素、数据对象、数据结构；
- 逻辑结构与存储结构；
- 集合、线性、树、图四类逻辑结构；
- ADT 的“规定对象、关系和操作，不规定实现”；
- 数据运算与算法的区别；
- 时间/空间复杂度、最好/平均/最坏情况、O/Ω/Θ。

### 需要校正

- `O`、`Ω`、`Θ` 应解释为渐进增长关系；不要把 `O` 直接等同“最坏情况”。
- “空间复杂度”要明确本书默认讨论辅助空间；若题目把输入空间算入总空间，要按题目口径。
- “顺序、链式、索引、散列”不是完全互斥的四个盒子；索引、散列更像组织/定位方式，可能建立在顺序或链式存储之上。
- `struct`、指针、动态分配只属于实现工具，不应在知识树上和线性、树、图并列。

### 拟定知识树

```text
绪论
├─ 数据对象
│  ├─ 数据项
│  ├─ 数据元素
│  └─ 数据对象
├─ 数据结构
│  ├─ 逻辑结构：集合 / 线性 / 树 / 图
│  └─ 存储表示：顺序 / 链式 / 索引 / 散列
├─ ADT
│  ├─ 数据对象
│  ├─ 逻辑关系
│  └─ 操作及其效果
└─ 算法评价
   ├─ 正确性与基本特征
   ├─ 时间复杂度
   ├─ 辅助空间复杂度
   └─ 最好 / 平均 / 最坏 + O / Ω / Θ
```

### 建议图解

- 一张“对象→关系→ADT→实现→算法→评价”的纵向关系图；
- 一张“逻辑结构 vs 存储实现”的对照小图。

## 第3章 栈、队列和数组

### 当前评价

- **结构：两条并列主线已经写对。** 受限线性表与多维下标映射没有被硬写成递进关系。
- **内容：基本正确，但栈/队列状态、循环队列约定和数组映射目前主要靠文字，复习时不够直观。**
- **主要风险：** “数组可实现堆”会让读者提前把第8章堆排序混入本章；需要改为“数组是底层表示之一，堆的逻辑约束在第8章集中解释”。

### 必须保留

- 栈：LIFO、顺序栈、共享栈、链栈、括号/表达式/递归；
- 队列：FIFO、顺序队列、链队列、循环队列；
- 循环队列的 `front/rear` 约定、判空、判满、有效长度；
- 数组行优先/列优先地址映射；
- 特殊矩阵与稀疏矩阵压缩；
- BFS 用队列、DFS 用栈或递归。

### 需要补充或校正

- 用一个统一约定画出循环队列的空、非空、满三种状态；
- 明确双端队列是操作约束的变体；优先队列不属于普通 FIFO，堆作为其常见实现放到第8章关联；
- 数组地址公式必须同时标出下标起点、维度、存储顺序和元素宽度；
- 特殊矩阵压缩要区分“存储节省”和“访问公式增加”；
- 稀疏矩阵三元组适合稀疏表示，不自动意味着每种运算都更快。

```text
│  │  └─ 括号、表达式、递归
│  ├─ 队列：一端进、一端出，FIFO
│  │  ├─ 顺序队列 / 链队列
│  │  ├─ 循环队列：空间复用
│  │  └─ 双端队列：两端受限操作
│  └─ 结构复用：BFS 用队列，DFS 用栈/递归
└─ 数组与矩阵
   ├─ 多维下标 → 线性偏移
   ├─ 特殊矩阵压缩
```

## 第8章 排序

- **主要风险：** 复杂度表若不绑定“标准实现”和“增量序列/基准/稳定分配”等条件，容易被背成绝对结论。

### 必须保留

- 关键字、记录、内部/外部排序；
- 时间、空间、稳定性；
- 直接插入、折半插入、希尔；
- 冒泡、快速；
- 简单选择、堆排序；
- 归并；
- 基数、计数（按教材范围标主干或补充）；
- 初始归并段、多路归并、败者树、置换-选择、最佳归并树。

### 需要补充或校正

- 用同一组数据展示“有序区扩大”的直接插入过程；
- 快速排序必须画一次划分，说明基准选择影响最好/最坏；
- 堆排序图要明确完全二叉树形状来自第5章，堆序是新增约束；
- 归并图要展示两个有序段如何合并；
- 希尔复杂度必须写“依赖增量序列”，不能给唯一固定阶；
- 基数排序必须强调每趟分配稳定；计数排序必须绑定值域大小；
- 外部排序按“减少磁盘 I/O”组织，区分置换-选择生成初始段、败者树选择下一条、最佳归并树安排合并顺序；
- 排序表中把“标准实现”与“可变实现”说明清楚，例如快速排序稳定性取决于实现，但常规原地版本不稳定。

## 四、统一排版方案

- 每章保留：本章问题 → 一句话主线 → 知识树 → 先看结论 → 知识展开 → 必要比较 → 易错边界 → 跨章连接。
- 在“知识树、知识展开、重要方法比较、易错与边界、跨章节连接”等一级分区前加入低对比度浅灰细线。
- 不给每个小标题加线，避免页面被切成碎片。
- 蓝色表示核心概念，绿色表示过程/算法，红色表示限制/易错，紫色表示跨章关联。
- 图旁只解释图中的状态、操作顺序、条件和代价；图片失效时，正文仍能独立阅读。
