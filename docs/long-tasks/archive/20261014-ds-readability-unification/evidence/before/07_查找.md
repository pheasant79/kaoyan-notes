## 先看结论

- <span style="color:#2563EB"><strong>查找方法由组织方式和任务共同决定：</strong></span>先问是否有序、是否要动态更新、是否需要范围查询，以及数据在内存还是外存。
- <span style="color:#DC2626"><strong>折半查找有两个同时成立的前提：</strong></span>关键字有序，并且能快速随机访问中间位置；普通链表不满足后者。
- <span style="color:#16A34A"><strong>树高决定树形查找的基本量级：</strong></span>普通 BST 的基本操作为 `O(h)`，不平衡时可退化到 `O(n)`；AVL 和红黑树通过平衡规则限制高度。
- <span style="color:#2563EB"><strong>B/B+ 树按块访问组织多路索引：</strong></span>外存查找常关注访问了多少块，而不只是结点内部比较了多少次。
- <span style="color:#DC2626"><strong>散列平均 `O(1)`不是无条件保证：</strong></span>它依赖散列函数、装填因子和冲突处理；最坏情况下仍可能检查 `O(n)` 个记录。

## 知识展开

<a id="search-basics"></a>
**查找表与评价口径。** 查找表由记录组成；记录中的**关键字**用于标识或比较目标，关键字可以是唯一字段，也可以只是排序字段之一。查找成功是找到符合条件的记录，查找失败是确认目标不存在。

**平均查找长度（ASL）**是按查找情形的概率加权后的平均比较次数。若第 `i` 种情形的概率为 `p_i`，执行它时比较 `c_i` 次，则 `ASL = Σ p_i c_i`。成功查找与失败查找通常分别计算；题目若把一次散列探测或一次外存块读作为主要操作，也要相应改用探测次数或块访问数，不能混用口径。

<a id="linear-search"></a>
**顺序查找。** 从一端开始逐项比较，找到目标即停止；扫完整张表仍未找到，才判定失败。它不要求有序，可用于顺序表或链表。长度为 `n` 时最坏比较 `n` 次，故最坏时间 `O(n)`。若成功目标等概率且每项只出现一次，成功 ASL 为 `(n+1)/2`；失败查找通常要检查全部 `n` 项。若记录访问概率不均，按访问频率调整次序可能降低平均比较次数，但会改变记录顺序。

顺序表实现可设置**哨兵**：把待查关键字暂存于表尾，循环比较时不必每轮另判越界；它减少边界判断，不会改变最坏 `O(n)` 的比较量级。哨兵会占用或临时改写一个位置，必须保存并恢复被覆盖的数据。

<a id="binary-search"></a>
**折半查找。** 在按关键字有序的顺序表中，维护尚可能包含目标的区间 `[low, high]`。每次取中点 `mid`：相等则成功；目标较小就令 `high = mid - 1`；目标较大就令 `low = mid + 1`。区间每轮约缩小一半，迭代查找的最坏比较次数为 `O(log n)`，循环变量式实现的辅助空间为 `O(1)`。

![有序表 4、9、13、18、25、31、37、42、56 的折半查找区间：查找 31 时先比较中点 25，保留右半区；再比较 37，保留左侧候选；最后命中 31。](assets/ch07/01-binary-search.svg)

图中的区间两端均为候选下标；每次比较都能排除一半左右的候选项。**有序但不能快速访问中点**时，比较次数的推导不代表总运行时间为 `O(log n)`：链表要先沿链接走到中间位置，位置访问本身可能需要线性时间。频繁插入、删除也可能要付出维护有序顺序的移动代价。

<a id="block-search"></a>
**分块查找。** 把记录划分为若干块，块内可以无序，但各块的关键字范围按序排列；索引保存每块的边界或最大关键字。先查索引确定候选块，再在块内顺序查找。若有 `b` 块、每块约 `s` 条记录，顺序查索引加块内扫描的最坏量级为 `O(b+s)`；对有序索引折半后约为 `O(log b+s)`，其中块内仍要扫描。均匀分块且用顺序索引时，令块数和块长都约为 `√n` 可使这两部分的量级平衡；具体 ASL 还取决于索引查找方式和块内目标分布。

<a id="binary-search-tree"></a>
**二叉查找树（BST）。** 对互异关键字，任一结点左子树中的关键字均小于该结点，右子树中的关键字均大于该结点，且左右子树也分别满足此性质。由根开始比较，每次进入左子树或右子树，路径长度受树高 `h` 控制；查找和插入为 `O(h)`。普通 BST 不自动平衡：若按递增关键字依次插入，会形成近似单链，`h=O(n)`；形状较平衡时 `h=O(log n)`。

**插入**沿查找路径走到空链接，把新结点接在那里；在不考虑平衡维护时，代价为 `O(h)`。若允许重复关键字，必须明确重复项放在哪侧、是否计数或存入同一记录集合，比较规则否则不完整。

**删除**分三种结构处理：叶结点直接摘除；仅有一个孩子时，用孩子接替被删结点；有两个孩子时，以右子树最小结点（中序后继）或左子树最大结点（中序前驱）替换关键字/记录，再删除那个至多只有一个孩子的替代结点。查找替代结点和改接链接仍沿树高进行，整体 `O(h)`。

![BST 删除双孩子结点 40：右子树中序后继 45 替代 40；随后从原位置摘除 45，原来的 45 右孩子 47 接到其父结点 50。](assets/ch07/02-bst-delete.svg)

用后继替换时，中序次序保持不变；若结点保存多字段记录，替换的关键字与记录信息必须保持一致，不能只改关键字却留下另一条记录的数据。

<a id="avl-tree"></a>
**AVL 树。** AVL 是严格平衡的 BST：每个结点左右子树高度差的绝对值至多为 1。平衡使高度保持 `O(log n)`，因此查找、插入、删除的主路径为 `O(log n)`；插入或删除还需检查祖先并可能旋转。采用 `BF = h(left) - h(right)` 的约定时，失衡结点及其较高孩子的方向决定旋转：

| 失衡路径 | 修复 | 旋转前后的关键结构 |
|---|---|---|
| LL：左孩子的左侧更高 | 对失衡结点右旋 | 左孩子上升 |
| RR：右孩子的右侧更高 | 对失衡结点左旋 | 右孩子上升 |
| LR：左孩子的右侧更高 | 先左旋左孩子，再右旋失衡结点 | 中间孙结点上升 |
| RL：右孩子的左侧更高 | 先右旋右孩子，再左旋失衡结点 | 中间孙结点上升 |

上述名称描述从失衡结点向下的路径。旋转会改变局部父子链接，但保持中序关键字次序。插入时通常修复从底向上遇到的第一个失衡祖先；删除后高度变化可能继续向上传播，不能假设只需一次局部修复就结束。

**红黑树（按教材范围展开）。** 若所用教材、课程或考纲明确涉及，再掌握红黑性质及插入删除修复；否则作为平衡 BST 的补充关联即可。典型约定包括根与外部 NIL 叶为黑、红结点不能有红孩子、从任一结点到其后代 NIL 的路径含相同黑结点数。它允许比 AVL 更宽松的局部形状，但仍把高度限制在 `O(log n)`。不同实现的 NIL 表示和操作细节可不同，做题以指定教材约定为准。

<a id="multiway-tree"></a>
**B 树与 B+ 树。** 多路查找结点在一次外存块读取中保存多个分隔关键字和孩子指针，分支数增大、树高降低，因而减少从根到叶所需的块访问。B 树的关键字可出现在内部结点；查找可能在内部结点命中。插入导致结点超出容量时分裂，删除导致占用不足时可向兄弟借关键字，或与兄弟合并；维护目标是满足结点占用约束并保持叶层同深。

若教材规定“`m` 阶”表示**最多 `m` 个孩子**，则非根内部结点通常至少有 `ceil(m/2)` 个孩子、最多 `m` 个孩子，`k` 个孩子之间有 `k-1` 个关键字；根是例外。若教材对“阶”的定义不同，最小占用公式会随约定改变，必须先核对定义。

B+ 树通常把完整记录或记录指针集中放在叶层，内部结点主要作导航；叶结点按关键字相连，适合等值查找与范围扫描。具体教材可能在内部结点是否保存数据、叶中保存什么方面采用不同表述。两者的主要比较成本应按树高、结点内搜索和实际块读写分析；不能直接把内存模型中的结点比较次数当作 I/O 次数。

<a id="hash-search"></a>
**散列查找。** 散列函数 `H(key)` 把关键字映射到表中槽位或桶号。常见除留余数法将关键字映射为 `key mod m`，但取模表长和关键字分布若选择不当，仍可能造成大量冲突。**冲突**是不同关键字得到同一地址；散列函数不能保证不存在冲突，查找过程必须使用与插入一致的冲突规则。

![散列表冲突处理示意：关键字 18、28、38 经相同初始地址映射；开放定址沿探测序列找到后续槽位，链地址则在同一桶后连接记录。](assets/ch07/03-hash-collision.svg)

**装填因子**通常写为 `α = n/m`，其中 `n` 是已存记录数、`m` 是槽位数。开放定址通常要求 `α < 1`；α 越接近 1，空槽越少，探测序列更容易变长。链地址可让一个桶连接多条记录，α 可以大于 1，但长链仍会增加比较次数。良好散列分布、受控 α 和合适的冲突策略下，散列查找的平均比较/探测次数可保持常数级；这不是对最坏情况的保证。

- **开放定址**把冲突记录继续放在散列表自身的槽位中。线性探测按固定步长逐槽查找，简单但容易形成主聚集；平方探测改变步长，可缓和部分聚集，但能否覆盖所有槽位取决于表长、公式和装填限制；双重散列由第二个散列值确定步长，步长应与表长互素，才能遍历全部槽位。查找必须沿同一探测序列进行。
- **链地址**把映射到同一桶的记录放在链表或其他容器中。桶内查找的代价由链长和组织方式决定；删除通常可从链中摘除目标，不会截断其他桶内记录的查找路径。
- **开放定址删除**通常不能把已占用槽直接恢复为“从未使用”：后来插入的冲突记录可能依赖经过该槽才能被找到。用“已删除”标记可允许搜索继续、并让插入复用该槽；随着标记积累，可通过重散列清理。

## 重要方法比较

下表的时间复杂度是常见实现的量级；查找成功和失败的 ASL 还取决于各情形概率。涉及外存时，块访问数与 CPU 比较次数分开看。

| 方法 | 前提 / 更新特征 | 主要代价 | 强项与限制 |
|---|---|---|---|
| 顺序查找 | 无须有序；表可静态或动态 | 最坏 `O(n)` 比较 | 结构要求低；访问频率可影响平均 ASL |
| 折半查找 | 关键字有序且支持 `O(1)` 位置访问 | 最坏 `O(log n)` 比较 | 定位快；顺序表插删要维护次序，链表中点访问昂贵 |
| 分块查找 | 块间有序、有索引；块内可无序 | 约 `O(b+s)`，或索引折半时 `O(log b+s)` | 在索引成本与块内扫描间折中 |
| 普通 BST | 按关键字动态插入；不强制平衡 | `O(h)`，最坏 `O(n)` | 结构直观、支持有序遍历；高度受插入次序影响 |
| AVL / 红黑树 | 插删时维护平衡 | 基本操作最坏 `O(log n)` | 适合动态有序查找；更新需调整，平衡规则不同 |
| B / B+ 树 | 多路结点适配块存储 | 主要看树高与块访问 | 外存索引、范围访问；节点分裂/借位/合并维护较复杂 |
| 散列 | 以等值查找为主；函数和冲突策略固定 | 平均可为 `O(1)`，最坏 `O(n)` | 不保持全序，不适合直接做范围查找或有序遍历 |

<a id="asl"></a>
**ASL 的使用。** 成功 ASL 对所有可能成功的目标求加权平均；失败 ASL 对各个失败区间或失败探测终止情形求加权平均。顺序查找在成功目标等概率时可直接用 `(n+1)/2`；BST 的成功查找长度对应结点层数，失败查找还要考虑空链接所在的外部结点；开放定址散列的 ASL 按探测次数统计。只有题目给定概率相同、结构和计数口径一致时，才可直接套对应平均值。

<a id="boundaries"></a>
## 易错与边界

- **有序不等于顺序存储：** 链表也可以逻辑有序，但不因此获得快速随机访问能力。
- **折半的对数比较不等于任何表示上的对数时间：** 每轮还要能快速访问中点。
- **BST 不是自平衡树：** `O(log n)` 需要高度为对数级；普通 BST 的最坏高度为 `n` 量级。
- **AVL 与红黑树不要互换规则：** AVL 限制每个结点的左右高度差；红黑树依靠颜色路径约束整体高度。
- **B 树“阶”的约定先看定义：** 最大孩子数、关键字数和最少占用不可脱离教材口径。
- **散列不是有序索引：** 平均等值定位快，不代表能高效找某范围内的全部记录。
- **删除标记不是空槽：** 对开放定址而言，标记让查找继续探测，直接清空可能导致漏查。
- **ASL 的分母和操作单位要清楚：** 成功/失败概率、关键字比较、散列探测和磁盘块读取不能混为一个数。
