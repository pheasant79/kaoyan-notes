# 第1章 绪论

> **本章要解决的问题：** 数据、数据之间的关系、操作规范、具体表示和算法代价，分别处在什么层次？

<span style="color:#2563EB"><strong>主线：</strong></span>
数据对象 → 逻辑关系 → ADT 操作规范 → 存储实现 → 算法 → 正确性与复杂度。

## 知识树

```text
绪论：建立分析数据结构的共同语言
├─ 数据对象
│  ├─ 数据项 → 数据元素 → 数据对象
│  └─ 数据类型 → 值的集合 + 允许的操作
├─ 数据结构
│  ├─ 逻辑结构 → 元素之间是什么关系
│  └─ 存储结构 → 关系在计算机中怎样表示
├─ ADT → 规定数据对象、逻辑关系、操作效果
├─ 算法 → 用有限步骤实现操作
└─ 算法评价
   ├─ 正确性、健壮性等
   ├─ 时间复杂度
   ├─ 辅助空间复杂度
   └─ 输入情况：最好 / 平均 / 最坏
      渐进记号：O / Ω / Θ
```

<hr style="border:0;border-top:1px solid #D1D5DB;margin:28px 0 16px;">

## 先看结论

- <span style="color:#2563EB"><strong>数据结构不是代码写法：</strong></span>它描述数据元素及其关系；同一关系可以有不同存储实现。
- <span style="color:#2563EB"><strong>逻辑结构与存储结构回答不同问题：</strong></span>前者说“怎样组织”，后者说“怎样表示”。
- <span style="color:#16A34A"><strong>ADT 与算法也不同：</strong></span>ADT 规定操作的含义，算法给出完成操作的步骤。
- <span style="color:#DC2626"><strong>复杂度有两个维度：</strong></span>最好/平均/最坏描述输入情况；O/Ω/Θ 描述增长界，不能把 O 直接等同于最坏情况。

<hr style="border:0;border-top:1px solid #D1D5DB;margin:28px 0 16px;">

## 概念坐标：从问题到实现

![数据结构概念关系图：数据对象经逻辑关系形成数据结构，由ADT规定操作，再选存储实现并设计算法，最后评价正确性和代价。](assets/ch01/01-concept-map.svg)

用“学生名单按学号查找”作例子：

1. **数据对象：** 学生记录；学号、姓名等是数据项。
2. **逻辑关系：** 若只要求一组记录，可能是集合；若按名次排列，则另有先后关系。
3. **ADT：** 规定可以查找、插入、删除记录，以及这些操作应产生什么结果。
4. **存储实现：** 可用连续数组、链式结点或索引组织。
5. **算法：** 决定逐条扫描、折半定位，或通过索引缩小范围。
6. **评价：** 分析操作是否正确，以及比较次数、搬移量和额外空间。

这条链解释了为什么“查找”不属于逻辑结构：它是对数据执行的操作；“顺序表”也不是逻辑关系，而是实现方式。

<hr style="border:0;border-top:1px solid #D1D5DB;margin:28px 0 16px;">

<a id="data-levels"></a>
## 数据的层次与数据类型

- **数据项：** 数据中具有独立含义的最小单位，例如学号。
- **数据元素：** 通常作为一个整体处理的基本单位，例如一条学生记录。
- **数据对象：** 性质相同的数据元素的集合，例如全班学生记录。
- **数据结构：** 存在特定关系的数据元素集合。
- **数据类型：** 一组值以及作用于这些值的操作。它可描述单个值，也可描述更复杂的对象。

因此，数据类型与数据结构相关但不等同：前者强调值及可执行操作，后者强调多个数据元素之间的组织关系。

<hr style="border:0;border-top:1px solid #D1D5DB;margin:28px 0 16px;">

<a id="logical-structure"></a>
## 逻辑结构：元素之间怎样关联

逻辑结构不依赖元素在内存中的地址。

| 结构 | 关系特征 | 典型例子 |
|---|---|---|
| 集合 | 只说明元素属于同一集合，不规定前后或层次关系 | 一组互不排序的记录 |
| 线性结构 | 除首尾外，每个元素有唯一直接前驱和后继 | 线性表、栈、队列、串 |
| 树形结构 | 形成层次关系，一个结点可有多个孩子 | 文件目录、组织层级 |
| 图状结构 | 元素之间可有一般多对多关系 | 道路网络、社交关系 |

<span style="color:#DC2626"><strong>易错：</strong></span>
栈、队列虽然限制了操作位置，其底层逻辑仍建立在线性关系上；“受限操作”不是新的存储结构。

<hr style="border:0;border-top:1px solid #D1D5DB;margin:28px 0 16px;">

## 存储结构：关系怎样落实到计算机中

<a id="storage-structure"></a>
存储实现需要表示数据元素，也要让所需关系和操作可以实现。常见方式及其取舍：

- **顺序存储：** 连续单元配合位置计算表示关系；按位访问方便，插删可能搬移元素。
- **链式存储：** 结点保存数据和链接；不要求物理相邻，按位访问通常要沿链接查找。
- **索引组织：** 额外保存关键字、范围或位置之间的索引信息；可加快定位，但需要空间并维护索引。
- **散列组织：** 通过散列函数把关键字映射到槽位或桶；适合等值定位，但必须处理冲突，通常不支持高效有序范围查询。

这些方式不一定彼此排斥。例如，索引本身可以顺序存放，散列桶也可以用链表处理冲突。

<hr style="border:0;border-top:1px solid #D1D5DB;margin:28px 0 16px;">

<a id="adt"></a>
## ADT、数据运算与算法

**抽象数据类型（ADT）** 描述：

- 数据对象是什么；
- 对象间有什么逻辑关系；
- 可以执行哪些操作；
- 每种操作的输入、输出和效果。

ADT 不指定数组、指针或某种编程语言。选定表示方式后，才为操作设计具体算法。

| 层次 | 回答的问题 | 例子 |
|---|---|---|
| 数据运算 | 要完成什么动作？ | 在线性表中插入一个元素 |
| 算法 | 按什么步骤完成？ | 找位置、移动后缀、写入元素 |
| 程序实现 | 如何用语言表达步骤？ | 数组赋值、循环或指针操作 |

算法通常要求有穷、确定、可行；还需要有输入和输出。实际评价还要检查正确性、健壮性、可读性和效率。

<hr style="border:0;border-top:1px solid #D1D5DB;margin:28px 0 16px;">

<a id="complexity"></a>
## 时间与空间复杂度

复杂度讨论的是**规模扩大时，资源需求怎样增长**。先确定问题规模，再分析基本操作次数或额外存储量。

- **时间复杂度：** 常用基本操作次数随规模 `n` 的增长阶数表示。
- **空间复杂度：** 本复习资料默认按辅助空间口径，计入临时数组、辅助结构和递归栈，不把输入本身重复算作额外空间。
- **最好/平均/最坏：** 固定规模下，分别讨论最有利输入、按给定分布取平均、最不利输入。平均情况必须依赖概率模型。

常见分析抓手：

- 顺序语句的代价相加后保留增长最快项；
- 循环要看迭代次数及每次操作代价；
- 嵌套循环要看循环变量范围，不能只数层数；
- 递归要写清子问题规模和调用层数，结合递推关系分析。

<a id="asymptotic"></a>
### O、Ω、Θ：增长界，不是输入情况

- `O(g(n))`：渐进上界；
- `Ω(g(n))`：渐进下界；
- `Θ(g(n))`：渐进紧确界，增长阶上下相符。

“最坏情况”是在所有同规模输入中选最不利者；`O` 是增长界。两者可组合成“最坏情况为 `O(n²)`”，但不是同一概念。严格地说，`O` 本身只表达上界，并不自动表示该算法实际达到这个阶。

典型增长速度由慢到快：

`O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ)`

<hr style="border:0;border-top:1px solid #D1D5DB;margin:28px 0 16px;">

## 易错与边界

- 逻辑结构描述关系；顺序、链接、索引和散列描述表示或组织方式。
- ADT 说明“操作应有何效果”；算法说明“怎样做到”；程序才是语言层面的具体写法。
- 复杂度表达需要绑定规模、输入情况和实现条件。
- 辅助空间与总空间口径不同；本资料默认计辅助空间。
- `struct`、指针、动态分配是实现工具，不是新的逻辑结构。
