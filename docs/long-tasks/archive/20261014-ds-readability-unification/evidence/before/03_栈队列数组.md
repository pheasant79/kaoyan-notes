# 第3章 栈、队列和数组

> **本章要解决的问题：** 限制线性结构的操作位置会带来什么性质？多维下标又如何映射到连续存储？

<span style="color:#2563EB"><strong>主线：</strong></span>
栈与队列是按操作规则划分的受限线性表；数组与矩阵是按下标访问、并可压缩存储的数据表示。它们是并列主题。

## 知识树

```text
栈、队列和数组
├─ 受限线性表
│  ├─ 栈：一端进出，LIFO
│  │  ├─ 顺序栈 / 共享栈 / 链栈
│  │  └─ 括号、表达式、递归
│  ├─ 队列：队尾进、队头出，FIFO
│  │  ├─ 顺序队列 / 链队列 / 循环队列
│  │  └─ 双端队列：两端的操作受限变体
│  └─ 结构复用：BFS 用队列；DFS 用栈或递归
└─ 数组与矩阵
   ├─ 多维下标 → 一维地址偏移
   ├─ 特殊矩阵 → 利用规律压缩
   └─ 稀疏矩阵 → 只存非零元素
```

## 先看结论

- <span style="color:#2563EB"><strong>栈与队列的本质差异是次序：</strong></span>栈后进先出，队列先进先出，与顺序或链式存储无关。
- <span style="color:#16A34A"><strong>状态结构决定典型用途：</strong></span>栈保存尚未完成的嵌套/回退状态，队列保存等待按层或按到达顺序处理的对象。
- <span style="color:#DC2626"><strong>循环队列公式依赖约定：</strong></span>必须先明确 `front`、`rear` 含义以及是否留一个空位。
- <span style="color:#2563EB"><strong>数组地址公式是位置映射：</strong></span>下标起点、维度、存储顺序和元素宽度缺一不可。
- <span style="color:#DC2626"><strong>压缩节省空间不等于所有操作更快：</strong></span>访问常需先换算位置，矩阵运算也可能额外付出代价。

<hr style="border:0;border-top:1px solid #D1D5DB;margin:28px 0 16px;">

<a id="stack"></a>
## 栈：把最近尚未完成的状态先处理

栈只允许在栈顶插入和删除。插入叫**入栈**，删除叫**出栈**，其顺序为后进先出（LIFO）。

![栈的操作状态：依次压入 A、B、C 后 C 位于栈顶，出栈先得到 C；随后依次得到 B、A。](assets/ch03/01-stack.svg)

### 存储实现

- **顺序栈：** 用数组保存元素，以栈顶下标表示有效范围；要判断空栈、栈满和扩容。
- **共享栈：** 两个栈从同一数组两端向中间增长，可利用一方的空闲空间；相遇时才整体满。
- **链栈：** 通常在链表头部入栈、出栈，操作不必扫描到链尾；每个结点需要链接空间。

### 为什么栈适合嵌套和回退

- **括号匹配：** 左括号压栈；遇到右括号时必须与栈顶类型匹配；结束后栈还非空表示存在未闭合左括号。
- **表达式处理：** 运算符优先级、括号层级和待计算操作数都可暂存于栈。
- **递归：** 调用栈保存返回位置、参数及局部状态。递归深度为 `d` 时，辅助栈空间通常随 `d` 增长。
- **深度优先搜索：** 显式栈或递归记录“走到哪里、回退后继续什么”。

一次普通入栈/出栈在顺序栈未扩容、链栈不计分配器开销时为 `O(1)`。

<a id="queue"></a>
## 队列：按到达次序处理等待对象

普通队列在队尾插入、队头删除，遵循先进先出（FIFO）。链队列若同时维护队头与队尾，常规入队和出队可为 `O(1)`。

<a id="circular-queue"></a>
### 循环队列：让数组前部空位重新可用

采用常见的“容量 `N`、保留一个空位”约定：

- `front` 指向队头元素；
- `rear` 指向下一个入队位置；
- 空队列：`front == rear`；
- 满队列：`(rear + 1) mod N == front`；
- 队列长度：`(rear - front + N) mod N`；
- 可存元素数为 `N - 1`。

![循环队列状态：容量 6 留一个空位，rear 绕回数组首端复用已出队的位置；空、普通、满分别对应 rear 等于 front、两者之间有元素、下一步 rear 将追上 front。](assets/ch03/02-circular-queue.svg)

普通顺序队列只让 `rear` 向后移动时，队头出队留下的格子不能复用，可能在尾部到达数组边界时报告溢出，这是假溢出。循环队列通过取模让下标绕回。

<span style="color:#DC2626"><strong>边界：</strong></span>
若实现使用元素计数器、额外标志位或允许所有格均存元素，判空、判满和长度公式会不同，不能沿用留空位版本。

### 其他队列变体

- **双端队列：** 两端都可能允许插入/删除，但具体受限方式需看定义；不能一概当普通 FIFO。
- **优先队列：** 删除按优先级选择，而非按到达先后；它不属于普通队列语义。二叉堆是常见实现，集中见[第8章](08_排序.md#heap-sort)。

<a id="array-mapping"></a>
## 数组：把多维位置换算成线性偏移

数组提供按下标访问的元素序列。多维数组在内存中仍按一维次序排放，需要根据行优先或列优先规则计算地址。

![二维数组行优先存储：3行4列按 A00、A01、A02、A03、A10…排列；红框 A12 的偏移为 1×4+2。](assets/ch03/03-array-mapping.svg)

设二维数组有 `r` 行、`c` 列，元素宽度为 `w`，首地址 `B`，下标从 0 开始：

- **行优先：** `LOC(A[i][j]) = B + (i × c + j) × w`
- **列优先：** `LOC(A[i][j]) = B + (j × r + i) × w`

例如 3 行 4 列数组中的 `A[1][2]`，行优先偏移为 `1×4+2=6` 个元素；再乘 `w` 才是字节/存储单位偏移。

推广到多维时，行优先会把最后一维变化视为最内层连续；列优先则把第一维视为最内层连续。先确定题目所用下标范围，再代公式。

<a id="matrix-compression"></a>
## 矩阵压缩：利用元素分布规律

### 特殊矩阵

- **对称矩阵：** `A[i][j] = A[j][i]`，只保存主对角线及一侧三角区即可。
- **三角矩阵：** 主对角线一侧为 0 或固定常量，可只存另一侧及对角线。
- **带状矩阵：** 非零元素集中在主对角线附近，只保存带内位置。

压缩后需先判断元素落在哪个区域，再将二维位置换算成一维位置。以 `n` 阶对称矩阵为例，独立元素数为 `n(n+1)/2`。

### 稀疏矩阵

当非零元数量 `t` 远小于 `r×c` 时，可存储三元组 `(行, 列, 值)`，空间约随非零元数量增长；若要频繁随机访问，则需搜索或额外索引。

<span style="color:#DC2626"><strong>取舍：</strong></span>
压缩主要减少存储量；访问换算、随机定位和矩阵运算的成本要单独分析。稀疏表示不意味着每种操作都更快。

<hr style="border:0;border-top:1px solid #D1D5DB;margin:28px 0 16px;">

## 性质与用途连接

| 问题特征 | 合适的结构工具 | 原因 |
|---|---|---|
| 最近遇到、最后完成的嵌套状态 | 栈 | 后进的状态先结束 |
| 先到先服务或按层扩展 | 队列 | 先进入者先处理 |
| 按多维坐标随机定位 | 数组 | 下标可计算为偏移 |
| 图中逐层访问顶点 | 队列 + BFS | 队列保存当前层待处理顶点 |
| 深入并在死路回退 | 栈/递归 + DFS | 保存返回与待续状态 |

<a id="boundaries"></a>
## 易错与边界

- 顺序/链式是存储方式；LIFO/FIFO 是操作规则。
- 循环队列不是循环链表：一个复用数组下标，一个让尾结点链接回入口。
- 数组下标连续，不代表元素关键字有序。
- 栈的递归应用受最大调用深度影响；不能只根据递归调用次数总计就下结论。
- 堆是带父子堆序的完全二叉树，不是本章的栈；“堆区”也不是二叉堆。
