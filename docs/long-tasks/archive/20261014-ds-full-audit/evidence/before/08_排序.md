# 第8章 排序

> **本章要解决的问题：** 怎样按关键字组织记录次序，哪种排序方法适合当前数据和存储条件？

<span style="color:#2563EB"><strong>一句话主线：</strong></span>
无序记录 → 形成有序部分 → 扩大有序范围 → 比较机制、复杂度、稳定性和存储条件 → 选择算法。

[返回全书总览](00_全书总览.md)

## 先看结论

- <span style="color:#2563EB"><strong>必须掌握：</strong></span>排序算法要同时看时间复杂度、辅助空间、稳定性和适用数据特征。
- <span style="color:#16A34A"><strong>必须掌握：</strong></span>直接插入是在有序前缀中插入；快速排序靠划分；归并排序靠合并；堆排序靠堆调整。
- <span style="color:#DC2626"><strong>必须掌握：</strong></span>快速排序平均快但最坏可达 `O(n²)`；堆排序最坏 `O(n log n)` 但通常不稳定；归并排序需要辅助空间。
- <span style="color:#2563EB"><strong>必须掌握：</strong></span>外部排序的主要瓶颈是磁盘 I/O，不是只比较 CPU 时间。

## 知识主线

先判断两个维度：

- 数据能否全部装入内存：内部排序 / 外部排序；
- 是否依靠关键字比较：比较排序 / 非比较排序。

再按算法机制理解：

```text
插入：把新记录放入有序区
交换：通过交换消除逆序或划分区间
选择：从未排序区选出极值
归并：把有序段合成更大的有序段
分配：利用关键字的位或值域信息
```

<a id="sorting-criteria"></a>
## 排序评价

- **时间复杂度：** 比较、移动或分配操作随 `n` 的增长。
- **空间复杂度：** 辅助数组、递归栈等额外空间。
- **稳定性：** 相等关键字记录排序前后的相对次序是否保持。
- **内部/外部：** 数据是否能在内存中直接处理。

<span style="color:#DC2626"><strong>注意：</strong></span>
“稳定”只表示相等关键字的相对次序，不表示运行时间稳定，也不表示算法一定更快。

<a id="insertion-sort"></a>
## 插入类排序

### 直接插入排序

维护一个已有序前缀，依次取出下一条记录，将大于它的记录向后移动，再插入空位。

- 最好 `O(n)`，平均/最坏 `O(n²)`；
- 辅助空间 `O(1)`；
- 通常稳定；
- 数据规模较小或接近有序时很实用。

### 折半插入排序

用折半查找确定插入位置，但后续移动记录仍然存在。

- 比较次数可降到 `O(n log n)`；
- 移动最坏仍为 `O(n²)`；
- 通常稳定；
- 它不是把整个插入排序变成 `O(n log n)`。

### 希尔排序

按增量把记录分组，进行分组插入排序，再逐步缩小增量，最后增量为 1。

- 时间复杂度依赖增量序列；
- 常用实现辅助空间 `O(1)`；
- 通常不稳定；
- 不能笼统写成固定的 `O(n log n)`。

<a id="exchange-sort"></a>
## 交换类排序

### 冒泡排序

反复比较相邻记录，发现逆序就交换。一趟通常把一个极值推到边界。

- 加提前结束标志时最好 `O(n)`；
- 平均/最坏 `O(n²)`；
- 辅助空间 `O(1)`；
- 通常稳定。

### 快速排序

选择基准，通过划分把记录分到基准两侧，再递归处理左右区间。

- 平均时间 `O(n log n)`；
- 最坏时间 `O(n²)`；
- 递归栈平均 `O(log n)`，最坏 `O(n)`；
- 常规实现不稳定。

<span style="color:#DC2626"><strong>易错：</strong></span>
“快速”是平均性能特征，不代表任何输入都快；基准选择不佳时可能退化。

<a id="selection-sort"></a>
## 选择类排序

### 简单选择排序

每趟从未排序区选出最小或最大记录，放到有序区边界。

- 比较次数通常为 `Θ(n²)`；
- 辅助空间 `O(1)`；
- 通常不稳定；
- 移动次数可能比插入排序少。

<a id="heap-sort"></a>
### 堆排序

二叉堆是满足完全二叉树形状和父子堆序的结构：

- 大根堆：父结点不小于孩子；
- 小根堆：父结点不大于孩子；
- 根保存全局极值；
- 左右子树之间不要求整体有序。

堆排序通常建立大根堆，反复把堆顶与末项交换，缩小堆范围，再向下调整恢复堆序。

- 建堆 `O(n)`；
- 整体最坏 `O(n log n)`；
- 迭代调整时辅助空间可为 `O(1)`；
- 通常不稳定。

<span style="color:#8B5CF6"><strong>跨章：</strong></span>
堆借用第5章完全二叉树的形状，但增加了父子关键字约束；它不是第7章的 BST，也不是内存管理中的“堆区”。

<a id="merge-sort"></a>
## 归并排序

二路归并排序先把序列拆分，再把两个有序段合并为一个更大的有序段；也可以采用自底向上的迭代方式逐步扩大段长。

- 时间 `O(n log n)`；
- 数组实现通常需要 `O(n)` 辅助空间；
- 合并时相等元素优先取左段，可保持稳定。

<a id="non-comparison-sort"></a>
## 非比较排序

### 基数排序

把关键字拆成有限位，按位进行稳定分配和收集。常见 LSD 版本从低位到高位处理。

若关键字有 `d` 位、每位有 `r` 种取值，常见复杂度为 `O(d(n+r))`。

<span style="color:#DC2626"><strong>关键条件：</strong></span>
LSD 基数排序每一趟必须稳定，否则已经形成的低位次序会被破坏。

### 计数排序

对有限值域计数，再利用累计计数安排输出位置。若值域大小为 `K`：

- 时间通常为 `O(n+K)`；
- 辅助空间通常为 `O(n+K)`；
- 值域过大、远大于记录数时不适合。

<span style="color:#DC2626"><strong>范围边界：</strong></span>
计数排序是否属于重点要以所用教材和考试范围为准；不能仅凭某个目录中的星号推断必考或不考。

<a id="external-sort"></a>
## 外部排序

当待排序数据不能全部装入内存时，目标从“少做比较”转为“减少磁盘读写和归并次数”。

基本过程：

1. 生成若干初始归并段；
2. 对多个有序段进行多路归并；
3. 必要时继续归并，直到得到一个有序文件。

### 置换-选择

利用内存工作区持续选择可以接续当前归并段的最小记录；暂时不能接续的记录留到下一段。

它可能生成长于内存容量的初始归并段，长度取决于输入，不是固定的“两倍内存”。

### 败者树

维护各归并段当前记录的比较结果，快速选出下一条输出记录。更新败者树的 `O(log k)` 是每条记录的 CPU 代价，但外部排序还要计算 I/O。

### 最佳归并树

根据各初始段长度安排合并次序，使总归并读写量尽量小。其思想与哈夫曼树的带权合并相通；多路归并时必要时需要补充零长度虚段。

## 重要方法比较

| 算法 | 主要机制 | 最好/平均/最坏时间 | 辅助空间 | 稳定性 | 常见适用特点 |
|---|---|---|---|---|---|
| 直接插入 | 插入有序前缀 | `O(n)` / `O(n²)` / `O(n²)` | `O(1)` | 稳定 | 小规模、近乎有序 |
| 冒泡 | 相邻交换 | `O(n)` / `O(n²)` / `O(n²)` | `O(1)` | 稳定 | 教学和简单场景 |
| 快速 | 基准划分 | `O(n log n)` / `O(n log n)` / `O(n²)` | 递归栈 | 不稳定 | 平均性能好 |
| 简单选择 | 每趟选择极值 | `Θ(n²)` | `O(1)` | 通常不稳定 | 移动次数较少 |
| 堆排序 | 堆调整 | `O(n log n)` / `O(n log n)` / `O(n log n)` | `O(1)`（迭代） | 不稳定 | 需要最坏保证且空间紧张 |
| 归并排序 | 合并有序段 | `O(n log n)` | `O(n)`（数组常见） | 可稳定 | 需要稳定排序 |
| 希尔排序 | 增量分组插入 | 依赖增量序列 | `O(1)` | 不稳定 | 改善插入排序 |
| 基数排序 | 按位分配收集 | `O(d(n+r))` | 常见 `O(n+r)` | 依赖稳定分配 | 关键字可分解、范围受限 |

## 选型思路

- 数据规模小或近乎有序：优先考虑直接插入。
- 要求最坏 `O(n log n)` 且辅助空间紧张：可考虑堆排序。
- 要求稳定且能接受辅助空间：可考虑归并排序。
- 平均性能重要且能接受最坏退化风险：可考虑快速排序，并关注基准选择。
- 关键字位数或值域受限：考虑基数排序或计数排序。
- 数据不能全部进内存：使用外部归并，并优先关注 I/O。

<a id="boundaries"></a>
## 易错与边界

- “稳定”不是“性能稳定”，只描述相等关键字记录的相对次序。
- 快速排序靠划分，归并排序靠合并，堆排序靠堆调整，不能混写机制。
- 比较排序最坏情况的比较下界 `Ω(n log n)` 不约束利用位或值域信息的非比较排序。
- 外部排序不能只计算败者树的 CPU 代价，还要计算逐趟磁盘读写。
- 二叉堆只要求父子堆序，不要求左右子树整体有序。
- 排序负责重排记录；查找负责定位记录，二者目标不同。
