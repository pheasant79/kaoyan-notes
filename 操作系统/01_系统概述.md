## 先看结论

1. 操作系统是硬件资源的管理者，也是用户程序与硬件之间的受控接口。
2. 用户态不能直接执行特权指令；系统调用通过陷入机制进入内核态。
3. 外部中断来自当前程序之外，异常由当前指令执行引起，系统调用是程序主动请求内核服务。
4. 进程、地址空间、文件和设备不是孤立概念：系统调用创建或阻塞进程，I/O 完成又会唤醒进程。

## 知识展开

<a id="system-model"></a>
### 系统模型

操作系统向上提供进程、文件、虚拟内存和 I/O 接口，向下管理处理器、主存、外存和设备。复习时先区分三层：

- **硬件层**：CPU、主存、总线、设备控制器提供执行和传输能力；
- **内核层**：调度、地址转换、文件管理、中断处理和驱动程序控制资源；
- **用户层**：应用程序通过库函数和系统调用提出服务请求。

<a id="user-kernel"></a>
### 用户态与内核态

处理器用状态位区分权限。用户态运行普通应用代码；内核态可以执行特权指令、访问受保护页表和设备寄存器。

<span style="color:#d55263"><strong>边界：</strong></span>用户程序不能因为“知道设备地址”就直接访问设备。必须通过系统调用或由内核建立的映射访问，否则会触发保护异常。

<a id="system-call"></a>
### 系统调用

系统调用是用户程序请求内核完成受保护操作的接口。典型类别包括进程控制、文件操作、设备管理、信息维护和通信。

<a id="syscall-flow"></a>
#### 调用路径

```text
用户代码
→ 库函数封装
→ 陷入指令/系统调用号
→ 保存现场并切换内核态
→ 内核检查参数并执行服务
→ 设置返回值
→ 恢复现场并返回用户态
```

<span style="color:#269c72"><strong>做题信号：</strong></span>题目出现“打开文件、创建进程、申请内存、读设备”，先判断它是否需要内核权限；需要时通常对应系统调用。

<a id="interrupt-exception"></a>
### 中断与异常

中断、异常和系统调用都可能让 CPU 暂停当前控制流，转入处理程序，但来源不同。

<a id="entry-types"></a>
| 类型 | 来源 | 是否由当前指令引起 | 例子 |
|---|---|---:|---|
| 外部中断 | 外部设备或时钟 | 否 | 时钟中断、设备完成中断 |
| 异常 | 当前指令执行 | 是 | 缺页、除零、非法指令 |
| 系统调用 | 当前程序主动请求 | 是（主动陷入） | `read`、`fork`、`open` |

进入处理程序前，处理器至少需要保存返回所需的 PC、状态字和必要寄存器；具体保存位置取决于体系结构和内核实现。

<a id="execution-entry"></a>
### 程序执行入口

一个简化执行链如下：

1. 加载器建立进程的地址空间和初始寄存器；
2. PC 指向入口指令，进程进入就绪队列；
3. 调度器分配 CPU，进程在用户态执行；
4. 进程执行系统调用、发生异常或被时钟中断；
5. 内核处理请求，可能返回用户态，也可能让进程阻塞或就绪；
6. 进程结束后释放地址空间、文件和其他资源。

## 典型方法与短例

<a id="examples"></a>
### 短例1：判断是否跨越内核边界

题目：`memcpy`、`read`、普通函数调用中，哪一个必然需要系统调用？

判断：普通函数调用和 `memcpy` 在用户地址空间内完成，不必进入内核；`read` 请求设备或文件数据，必须由内核检查并执行，因此需要系统调用。

### 短例2：区分中断、异常和系统调用

题目：时钟到期、访问不存在的页、程序执行 `open` 分别属于什么？

答案：时钟到期是外部中断；访问不存在的页通常触发缺页异常；执行 `open` 是主动系统调用。关键不是“是否进入内核”，而是触发来源不同。

## 易错与边界

- 系统调用不是普通函数调用的同义词；它必然涉及受保护的内核服务入口。
- 缺页异常进入内核后可能把进程置为阻塞，页面装入完成后再唤醒；不是所有异常都直接终止进程。
- “内核态权限更高”不等于“内核可以忽略地址合法性和资源权限检查”。
- 现代系统可能用虚拟化、用户态驱动或异步 I/O 优化路径，但 408 题目仍应先按经典用户态—内核态模型判断。
