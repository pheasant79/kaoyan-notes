# 第5章 树与二叉树

> **本章要解决的问题：** 层次关系怎样表示和访问，又怎样服务编码与集合管理？

<span style="color:#2563EB"><strong>一句话主线：</strong></span>
树的层次关系 → 二叉树的左右结构 → 表示与遍历 → 线索化、哈夫曼树和并查集等应用。

## 先看结论

- <span style="color:#2563EB"><strong>必须掌握：</strong></span>树表示一对多层次关系；二叉树额外区分左、右位置，即使只有一个孩子也不能省略方向。
- <span style="color:#2563EB"><strong>必须掌握：</strong></span>满二叉树和完全二叉树是形状概念，不等于 BST 或二叉堆。
- <span style="color:#16A34A"><strong>必须掌握：</strong></span>遍历是访问规则；先序、中序、后序和层序的区别在于访问根、左子树、右子树的时机。
- <span style="color:#8B5CF6"><strong>必须掌握：</strong></span>BST、AVL、红黑树主归属是第7章；本章只提供一般树和二叉树性质。

## 知识主线

树相关知识按四条线展开：

- **结构：** 树、森林、二叉树及形状性质；
- **表示：** 双亲、孩子、孩子—兄弟和二叉链式表示；
- **访问：** 遍历、线索化和由遍历序列恢复结构；
- **应用：** 哈夫曼树、并查集，以及与查找、图算法的关联。

<a id="tree-basics"></a>
## 树、森林与二叉树

### 树

树由一个根和若干互不相交的子树构成：

- 非根结点恰有一个双亲；
- 一个结点可以有多个孩子；
- 结点的度是它拥有的孩子数；
- 树的度是所有结点度的最大值。

### 森林

森林是若干棵互不相交的树的集合。删除一棵树的根，可以得到由其子树组成的森林。

### 二叉树

二叉树是空树，或由一个根和两棵有明确左右位置的二叉子树构成。

<span style="color:#DC2626"><strong>注意：</strong></span>
二叉树的“左孩子”和“右孩子”是结构位置，不只是“第一个孩子”和“第二个孩子”。只有一个孩子时，也要区分它位于左边还是右边。

<a id="binary-shapes"></a>
## 二叉树形状

- **满二叉树：** 按常见教材口径，各层结点都达到该层允许的最大数量。
- **完全二叉树：** 除最后一层外均满，最后一层结点从左到右连续排列。

完全二叉树适合用数组表示，因为父子下标关系可以直接计算；但“完全”只限制形状，不限制关键字大小。

### 常用性质

若根所在层记为第 1 层，深度为 `h` 的二叉树最多有 `2^h - 1` 个结点。具体结点数、叶结点数和分支结点数还要结合题目给出的形状条件。

<a id="tree-storage"></a>
## 树的表示

### 一般树

- **双亲表示：** 每个结点保存双亲位置，找双亲方便；找全部孩子需要扫描或额外组织。
- **孩子表示：** 每个结点组织自己的孩子，枚举孩子方便，但结点结构可能不统一。
- **孩子—兄弟表示：** 保存“第一个孩子”和“下一个兄弟”，把一般树统一成二叉链式形式。

### 二叉树

- **顺序存储：** 适合完全二叉树，按下标计算父子位置；普通稀疏二叉树可能浪费大量空位。
- **链式存储：** 结点保存数据、左指针和右指针，适合一般形状。

<a id="traversal"></a>
## 二叉树遍历

- **先序：** 根 → 左子树 → 右子树。
- **中序：** 左子树 → 根 → 右子树。
- **后序：** 左子树 → 右子树 → 根。
- **层序：** 按层从上到下访问，通常使用队列。

### 遍历与结构恢复

在结点值互不重复时：

- 先序 + 中序可以唯一确定二叉树；
- 后序 + 中序可以唯一确定二叉树；
- 仅有先序和后序通常不能唯一确定二叉树。

恢复时先从中序序列确定左右子树范围，再递归处理对应区间。

<a id="threaded-tree"></a>
## 线索二叉树

普通二叉链式存储中可能有大量空指针。线索化可以把这些空指针改作指向遍历序列中的前驱或后继。

- 线索指针必须配合标志位区分“孩子链接”与“线索”；
- 中序线索树便于按中序寻找前驱和后继；
- 线索化不是改变逻辑树形，而是增强访问表示。

<a id="huffman"></a>
## 哈夫曼树

哈夫曼树用于构造带权路径长度最小的二叉树：

1. 每次选取权值最小的两棵树；
2. 合并成新树，权值为两者之和；
3. 将新树放回集合，重复直到只剩一棵树。

带权路径长度为各叶结点 `权值 × 根到叶路径长度` 的总和。哈夫曼编码利用不同长度的前缀码表示字符，任何码字都不是另一个码字的前缀。

<a id="union-find"></a>
## 并查集

并查集维护若干个互不相交的集合，核心操作是：

- **Find：** 找到元素所在集合的代表元；
- **Union：** 合并两个集合。

常用双亲森林表示集合：

- 根结点保存代表元；
- 非根结点保存双亲；
- 按秩/按大小合并，避免树过高；
- 路径压缩使后续查找更快。

<span style="color:#DC2626"><strong>复杂度边界：</strong></span>
只有在采用合并优化和路径压缩等条件下，才能使用近似常数的摊还复杂度结论；不能无条件写成每次严格 `O(1)`。

<a id="boundaries"></a>
## 易错与边界

- 满二叉树是“各层全满”；完全二叉树是“上层全满、末层靠左连续”，二者不能混用。
- 完全二叉树、BST、二叉堆分别限制形状、关键字范围和父子堆序。
- 遍历顺序不是存储结构；层序遍历使用队列，深度优先访问可用递归或栈。
- 哈夫曼树优化的是带权路径长度，不是结点总数或树高本身。
- 并查集是集合划分和合并结构，不等于普通二叉树遍历。
- BST、AVL、红黑树的完整查找性质集中在[第7章](07_查找.md#binary-search-tree)；二叉堆和堆排序集中在[第8章](08_排序.md#heap-sort)。
