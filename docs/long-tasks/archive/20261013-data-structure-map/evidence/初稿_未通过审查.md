## 第1章 绪论：建立全书坐标系

```text
本章要解决的问题：
“数据是什么、数据如何组织、怎样评价处理方法？”
↓
数据
├─ 数据项：描述一个对象的某个属性
├─ 数据元素：通常作为一个整体处理的基本单位
└─ 数据对象：具有相同性质的数据元素集合
↓
数据结构
├─ 逻辑结构：数据元素之间是什么关系
│  ├─ 集合：元素之间没有特定关系
│  ├─ 线性结构：一对一
│  ├─ 树形结构：一对多
│  └─ 图状结构：多对多
├─ 存储结构：逻辑关系如何在计算机中表示
│  ├─ 顺序存储：相邻元素占用连续空间
│  ├─ 链式存储：通过指针/链接表示关系
│  ├─ 索引存储：用附加索引加快定位
│  └─ 散列存储：由关键字计算存储位置
└─ 数据运算：访问、查找、插入、删除、修改、遍历等
↓
抽象数据类型 ADT
├─ 数据对象：规定处理哪些数据
├─ 数据关系：规定数据之间的逻辑关系
└─ 数据操作：规定可以做什么
   └─ 只描述功能，不规定顺序表、链表等具体实现
↓
算法
├─ 为解决特定问题而设计的有限步骤
├─ 基本要求：有穷、确定、可行
├─ 正确性：对规定输入得到符合要求的结果
└─ 效率评价
   ├─ 时间复杂度：运行代价随问题规模 n 的增长趋势
   └─ 空间复杂度：额外存储空间随 n 的增长趋势
↓
渐进记号
├─ O：渐进上界，常用于描述最坏增长阶
├─ Ω：渐进下界
└─ Θ：渐进紧确界
```

**边界与关联：**

```text
线性表 ≠ 顺序表：
线性表是逻辑结构/抽象对象；
顺序表、链表是具体存储实现。

索引存储、散列存储：
第1章只作为存储结构分类；
索引查找、散列冲突处理放到第7章。

算法不是数据结构的下一级：
算法是利用数据结构解决问题的方法；
复杂度是评价算法的方法。
```

**实现关联备注：**

```text
C/C++ 中的 struct、指针、typedef 只是表达存储实现的工具；
它们不改变“逻辑结构—存储结构—操作”的概念层级。
```

## 第2章 线性表：同一逻辑结构的不同实现

```text
本章要解决的问题：
“一对一的线性关系，如何存储、访问和修改？”
↓
线性表
├─ 由同类数据元素组成的有限序列
├─ 除首元素外，每个元素有唯一直接前驱
├─ 除末元素外，每个元素有唯一直接后继
└─ 线性表只规定逻辑关系，不规定内存布局
↓
线性表 ADT 的基本操作
├─ 初始化、判空、求长度
├─ 按位读取、按值查找
├─ 插入、删除、修改
└─ 遍历、销毁
↓
顺序表：线性表的顺序存储实现
├─ 逻辑相邻 = 物理相邻
├─ 通过首地址和下标实现随机访问
├─ 按位访问：O(1)
├─ 按值查找：通常 O(n)
├─ 中间插入：后续元素后移，通常 O(n)
├─ 中间删除：后续元素前移，通常 O(n)
└─ 适合随机访问多、插入删除相对少的场景
↓
链表：线性表的链式存储实现
├─ 逻辑相邻，不要求物理相邻
├─ 结点 = 数据域 + 指针域
├─ 按位访问：从头沿链接移动，通常 O(n)
├─ 按值查找：通常 O(n)
├─ 已知结点/前驱后的插入删除：主要改指针，可 O(1)
└─ 适合长度变化大、插入删除多且不强调随机访问的场景
↓
链表的组织形式
├─ 单链表：只有后继链接
├─ 双链表：同时保存前驱和后继
├─ 循环链表：尾部链接回首部
└─ 静态链表：用数组下标模拟链接
```

**性质、条件与边界：**

```text
“链表插入删除快”有前提：
必须已经找到相关结点或必要前驱；
若还要从头寻找位置，整体仍可能是 O(n)。

按位查找 ≠ 按值查找：
顺序表按位访问可直接定位；
链表按位访问必须逐结点移动；
两者按值查找通常都要比较元素。

头指针、头结点不是新的逻辑结构：
它们是链表实现中的组织方式；
带头结点可统一首元结点的插入和删除边界。
```

**实现关联备注：**

```text
静态分配/动态分配描述的是空间申请方式；
不改变线性表是顺序实现还是链式实现。

LinkList 通常只是 LNode* 的类型别名；
“指针指向结点”不等于“指针本身就是结点”。
```

## 第3章 栈、队列和数组：受限线性结构与多维存储

```text
本章要解决的问题：
“当线性表的操作受到限制，或数据变成多维形式时，如何组织和访问？”
├─ 分支A：受限线性表
│  ├─ 栈
│  ├─ 队列
│  └─ 双端队列
└─ 分支B：多维数据存储
   ├─ 数组
   ├─ 特殊矩阵
   └─ 稀疏矩阵
```

### 受限线性表

```text
栈
├─ 后进先出 LIFO
├─ 插入和删除都在栈顶
├─ 顺序栈：数组 + 栈顶位置
├─ 链栈：链表 + 栈顶指针
└─ 典型应用
   ├─ 括号匹配：遇左括号入栈，遇右括号匹配栈顶
   ├─ 表达式转换与求值：保存运算符或操作数
   ├─ 函数调用/递归：保存调用现场
   └─ DFS：显式栈或递归栈
↓
队列
├─ 先进先出 FIFO
├─ 队尾入队、队头出队
├─ 顺序队列：数组实现
│  └─ 反复出队后可能出现“假溢出”
├─ 循环队列：首尾相接，重复利用空间
├─ 链式队列：结点链接，通常维护队头和队尾
├─ 双端队列：两端都可插入/删除
└─ 典型应用
   ├─ 层次遍历
   ├─ BFS
   ├─ 缓冲与消息排队
   └─ 调度中的等待队列
```

### 多维数据存储

```text
数组
├─ 同类元素组成的多维数据集合
├─ 通过下标访问
└─ 核心：下标组合 → 线性存储地址
   ├─ 行优先
   └─ 列优先
↓
特殊矩阵
├─ 对称矩阵：只存一侧元素
├─ 三角矩阵：只存三角区域
└─ 对角矩阵：只存主对角线附近元素
↓
稀疏矩阵
├─ 非零元素远少于零元素
├─ 直接存完整矩阵会浪费空间
└─ 可只存非零元素及其行、列位置
   ├─ 三元组表
   └─ 十字链表等更灵活表示
```

**定位提醒：**

```text
栈、队列：线性表的操作受限形式；
数组、矩阵：多维数据的存储问题。

BFS 使用队列；
DFS 通常使用栈或递归。

递归不是一种独立数据结构：
递归调用过程依赖系统调用栈。
```

## 第4章 串：字符序列与模式匹配

```text
本章要解决的问题：
“字符组成的线性序列如何存储、操作，并高效寻找子串？”
↓
串
├─ 由字符组成的有限序列
├─ 空串：长度为 0
├─ 空格串：含有空格字符，长度不一定为 0
├─ 主串：被查找的字符序列
├─ 子串：主串中连续的一段字符
└─ 模式串：用于匹配的目标序列
↓
串的基本操作
├─ 求长度、取字符
├─ 比较
├─ 连接
├─ 求子串
├─ 插入、删除
└─ 替换
↓
模式匹配
├─ BF/朴素匹配
│  ├─ 从主串的不同起点尝试
│  ├─ 逐字符比较
│  └─ 失配后重新移动并比较，可能重复利用很少
└─ KMP
   ├─ 利用模式串已经匹配部分的信息
   ├─ 失配时主串指针不回退
   ├─ next：确定模式串下一次比较位置
   ├─ nextval：进一步减少无效比较
   └─ 核心：利用最长相等真前缀与真后缀
```

**核心关系：**

```text
已经匹配了一段
↓
末尾失配
↓
已匹配部分内部仍可能存在可复用的前后缀
↓
模式串移动到合理位置继续比较
```

**边界与关联：**

```text
串匹配：在字符序列中寻找子串；
第7章查找：在记录表中按关键字定位记录。

KMP 的重点不是孤立背 next 数组，
而是理解“失配后为什么不必让主串指针回退”。
```

## 第5章 树与二叉树：层次关系和递归结构

```text
本章要解决的问题：
“一对多的层次关系如何表示、遍历和应用？”
↓
树
├─ 基本概念
│  ├─ 根、双亲、孩子、兄弟
│  ├─ 结点的度、树的度
│  ├─ 层次、深度、高度
│  └─ 路径、子树、森林
├─ 存储表示
│  ├─ 双亲表示
│  ├─ 孩子表示
│  └─ 孩子-兄弟表示
↓
二叉树
├─ 每个结点至多有两棵子树
├─ 左、右子树有明确次序
├─ 顺序存储：适合完全二叉树等结构
├─ 链式存储：结点保存左右孩子指针
└─ 结构性质
   ├─ 叶结点数、分支结点数之间的关系
   ├─ 第 i 层最多有多少结点
   ├─ 高度与结点数的上界关系
   ├─ 满二叉树：每层都达到最大结点数
   └─ 完全二叉树：最后一层从左到右连续排列
↓
遍历
├─ 先序：根 → 左 → 右
├─ 中序：左 → 根 → 右
├─ 后序：左 → 右 → 根
├─ 层序：按层访问，通常使用队列
└─ 遍历的结果可用于访问、表达式处理和结构转换
↓
树、森林与二叉树
├─ 树通过孩子-兄弟表示转换为二叉树
├─ 森林可转换为二叉树
└─ 二叉树也可按规则还原为树或森林
↓
特殊结构与应用
├─ 线索二叉树
│  └─ 利用空指针保存前驱/后继线索，便于遍历
├─ 哈夫曼树
│  ├─ 带权路径长度 WPL
│  ├─ 目标：构造 WPL 最小的二叉树
│  └─ 应用：哈夫曼编码
└─ 并查集
   ├─ 表示若干互不相交的集合
   ├─ 查找元素所属集合的代表元
   └─ 合并两个集合
```

**跨章节定位：**

```text
二叉排序树 BST：
第5章只把它看作特殊二叉树；
第7章完整学习其查找、插入、删除和性能。

AVL、红黑树：
属于平衡查找结构，主归属在第7章。

堆：
与完全二叉树有关；
主归属在第8章堆排序，不在本章展开排序过程。
```

**最重要的区分：**

```text
满二叉树：关注每层是否都满；
完全二叉树：关注最后一层是否从左到右连续；
二叉排序树：关注关键字大小关系；
堆：关注父子结点的局部大小关系。
```

## 第6章 图：多对多关系及其目标算法

```text
本章要解决的问题：
“多对多关系如何表示、遍历，并针对不同目标求解？”
↓
图的基本概念
├─ 顶点、边、弧
├─ 有向图、无向图
├─ 带权图、不带权图
├─ 度、入度、出度
├─ 路径、回路、简单路径
├─ 连通、连通分量
└─ 强连通、强连通分量
↓
图的存储结构
├─ 邻接矩阵
│  ├─ 判断两点是否相邻方便
│  ├─ 适合稠密图
│  └─ 空间通常为 O(V²)
├─ 邻接表
│  ├─ 只保存实际存在的边
│  ├─ 适合稀疏图
│  └─ 遍历邻接点效率较好
├─ 十字链表：有向图的链式表示
└─ 邻接多重表：无向图的链式表示
↓
图的遍历
├─ BFS
│  ├─ 使用队列
│  ├─ 按层扩展
│  └─ 可用于无权图最短边数路径
└─ DFS
   ├─ 使用栈或递归
   ├─ 沿一条路径深入
   └─ 可用于连通性、生成树等问题
↓
按问题目标选择算法
├─ 连通性/遍历
│  └─ BFS、DFS
├─ 最小生成树
│  ├─ Prim：从一个顶点逐步扩展
│  ├─ Kruskal：按边权从小到大选择并查集可辅助判环
│  └─ 目标：连接所有顶点且总权值最小
├─ 最短路径
│  ├─ Dijkstra：单源最短路径，不能直接处理负权边
│  ├─ Floyd：多源最短路径，动态规划式更新
│  └─ 目标：指定顶点之间的路径代价最小
├─ 拓扑排序
│  ├─ 适用于有向无环图
│  ├─ 顶点表示活动/任务
│  └─ 目标：按先后依赖给出合法顺序
└─ 关键路径
   ├─ AOE 网：边表示活动，顶点表示事件
   ├─ 分析工程总工期
   └─ 找出影响总工期的关键活动
```

**网络模型边界：**

```text
AOV 网：顶点表示活动，边表示先后关系 → 拓扑排序；
AOE 网：边表示活动，顶点表示事件 → 关键路径。

最小生成树 ≠ 最短路径：
前者要求整体连通且总边权最小；
后者要求某些顶点之间的路径代价最小。

BFS/DFS 是遍历方法；
Dijkstra/Floyd 是最短路径算法；
不能因为都“走图”就放在同一算法类别里。
```

## 第7章 查找：在已有数据中定位记录

```text
本章要解决的问题：
“面对不同组织方式的查找表，如何快速定位目标记录？”
↓
查找基本概念
├─ 查找表：记录的集合
├─ 关键字：用于比较和定位的字段
├─ 记录：一个完整数据元素
├─ 查找成功/失败
└─ 平均查找长度 ASL：完成一次查找所需的平均比较次数
↓
线性查找
├─ 顺序查找
│  ├─ 不要求关键字有序
│  ├─ 实现简单、适用范围广
│  └─ 平均/最坏比较次数通常为 O(n)
├─ 折半查找
│  ├─ 要求关键字有序
│  ├─ 要求能够快速访问中间位置
│  └─ 每次缩小一半区间，通常为 O(log n)
└─ 分块查找
   ├─ 块间有序
   ├─ 建立索引定位块
   └─ 块内再顺序查找
↓
树形查找结构
├─ 二叉排序树 BST
│  ├─ 左子树关键字小于根
│  ├─ 右子树关键字大于根
│  ├─ 中序遍历得到有序序列
│  └─ 形态可能退化，性能依赖树高
├─ AVL 树
│  ├─ 平衡二叉排序树
│  ├─ 通过旋转维持高度平衡
│  └─ 避免普通 BST 严重退化
├─ 红黑树〔关联/补充，按教材要求取舍〕
│  └─ 用颜色规则维持近似平衡
├─ B 树
│  ├─ 多路平衡查找树
│  └─ 减少外存访问次数
└─ B+ 树
   ├─ 记录通常集中在叶结点
   ├─ 叶结点可按序连接
   └─ 适合范围查找和外存索引
↓
散列查找
├─ 散列函数：关键字 → 散列地址
├─ 冲突：不同关键字得到同一地址
├─ 开放定址法：在表内继续探测空位置
├─ 链地址法：同一地址挂接冲突记录
└─ 性能受散列函数、装填因子和冲突处理影响
```

**方法选择：**

```text
无序、结构简单 → 顺序查找
有序且可随机访问 → 折半查找
分块有序 → 分块查找
动态插入删除且需要有序关系 → BST/AVL
外存、多路平衡 → B树/B+树
平均快速定位且不强调顺序 → 散列查找
```

**边界与关联：**

```text
索引存储：第1章的存储结构分类；
索引查找：本章的具体查找方法。

查找：定位记录，不负责重新排列记录；
排序：改变记录排列，为查找或后续处理创造条件。

BST、AVL 的“树”是结构背景，
但本章关注的是查找、插入、删除和性能。
```

## 第8章 排序：重新排列记录

```text
本章要解决的问题：
“如何把记录按关键字重新排列，并根据数据特点选择排序方法？”
↓
排序评价
├─ 时间复杂度：比较和移动等操作的增长代价
├─ 空间复杂度：辅助存储空间
├─ 稳定性：关键字相等的记录相对次序是否保持
└─ 存储环境
   ├─ 内部排序：数据基本能放入内存
   └─ 外部排序：数据不能全部放入内存
↓
内部排序
├─ 插入类
│  ├─ 直接插入：把下一个记录插入已有有序区
│  ├─ 折半插入：折半确定插入位置
│  └─ 希尔排序：按增量分组，逐步减少逆序
├─ 交换类
│  ├─ 冒泡排序：交换相邻逆序记录
│  └─ 快速排序：选基准并划分
├─ 选择类
│  ├─ 简单选择：每趟选出最小/最大记录
│  └─ 堆排序：建堆并反复调整堆顶
├─ 归并类
│  └─ 归并排序：分治拆分，再合并有序序列
└─ 分配类
   └─ 基数排序：按关键字位次分配与收集
↓
算法核心差异
├─ 快速排序：核心是划分
├─ 归并排序：核心是合并
├─ 堆排序：核心是堆调整
├─ 插入排序：核心是扩大有序区
└─ 基数排序：核心是分配和收集，不依赖直接比较
↓
外部排序
├─ 初始归并段：先把可装入内存的部分排好
├─ 多路归并：同时合并多个有序归并段
├─ 败者树：提高多路归并选择最小记录的效率
├─ 置换-选择：生成更长的初始归并段
└─ 最佳归并树：减少归并次数和外存访问
```

**方法选择：**

```text
数据近乎有序 → 插入类方法常有优势
平均追求较快 → 快速排序常用，但要注意退化
需要较稳定的性能 → 堆排序等
要求稳定 → 选择稳定算法，并检查实现方式
关键字位数固定、分配条件满足 → 基数排序
数据无法全部装入内存 → 外部排序
```

**边界与关联：**

```text
堆与完全二叉树有关，
但在本书主线中作为第8章堆排序的辅助结构。

稳定性不是速度；
“快”也不等于“稳定”。

败者树、置换-选择、最佳归并树：
都是外部排序的辅助机制，
不应和快速排序、堆排序当作同一类普通内部排序。

计数排序、红黑树等内容：
按你的教材是否明确讲授决定是否作为补充，
不为了“看起来完整”而抢占主干位置。
```

## 易混名词总表

| 容易混淆 | 应这样区分 |
|---|---|
| 线性表 / 顺序表 | 线性表是逻辑结构；顺序表是顺序存储实现 |
| 链表 / 静态链表 | 链表是链式逻辑实现；静态链表用数组下标模拟链接 |
| 头指针 / 头结点 | 头指针是指向链表的指针；头结点是链表中的辅助结点 |
| 栈 / 队列 | 栈是后进先出；队列是先进先出 |
| 栈 / 递归 | 栈是数据结构；递归是调用方式，运行时依赖调用栈 |
| 数组 / 顺序表 | 数组是具体存储形式；顺序表是带长度和操作规则的线性表实现 |
| 满二叉树 / 完全二叉树 | 满关注每层都满；完全关注最后一层从左到右连续 |
| BST / 堆 | BST按中序得到有序关系；堆只保证父子局部大小关系 |
| BFS / DFS | BFS按层扩展用队列；DFS沿路径深入用栈/递归 |
| 最小生成树 / 最短路径 | 前者优化整体连通的总边权；后者优化指定路径代价 |
| 拓扑排序 / 普通排序 | 拓扑排序依据有向依赖关系，不是按关键字大小排序 |
| 索引存储 / 索引查找 | 前者是存储结构分类；后者是具体查找方法 |
| 查找 / 排序 | 查找定位记录；排序重新排列记录 |
| 堆 / 堆排序 | 堆是结构；堆排序是利用堆进行排序的算法 |
| 稳定性 / 时间复杂度 | 稳定性描述相等关键字的相对次序；复杂度描述代价增长 |
| 内部排序 / 外部排序 | 前者数据主要在内存中；后者需要分批处理外存数据 |
