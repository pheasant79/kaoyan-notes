虚拟存储器与 地址体系

这份新 HTML 只做一件事：把 虚拟存储器、主存、磁盘、Flash 各自“地址到底长什么样”讲清楚。你最容易卡住的地方，其实不是某个公式，而是 不同层次的地址单位根本不一样。

核心结论先记住这句

虚拟地址不是磁盘地址；物理地址不是 Flash 页地址；扇区 / 页 / 行 / 字 / 字节这些词，属于不同存储层，各管各的。

做地址转换时，真正被转换的是 CPU 发出的虚拟地址 → 主存物理地址。磁盘和 Flash 主要扮演“背后存放数据”的角色，不直接拿来给程序当主地址空间用。

你现在最该分清

一层一个地址体系：

• CPU / 程序：虚拟地址

• 主存：物理地址

• 磁盘：LBA / 逻辑块号

• Flash：页 / 块 / 逻辑页映射

图 先建立一张总地图

先把你脑子里的图像改掉：地址不是“任何地方都一样的一串数字”。地址永远要挂在某种存储模型上看。

纠偏：你担心“各个地方地址考量不一样就没法转换”，其实正相反——正因为不一样，才需要转换表。页表、段表、FTL、磁盘控制器，本质上都是“把一种地址翻译成另一种地址”的机器。

0 地址到底长什么样

1）虚拟地址

不是“软件随便编的数字”，而是 CPU/程序在进程地址空间里使用的编号。

页式系统里最常见的形状：

[ 虚拟页号 VPN | 页内偏移 offset ]

页内偏移不变，变化的是“这一页映射到哪个物理页框”。

2）物理地址

这是 RAM 真实可访问的位置。对 CPU 来说，最终要落到这里。

页式系统里最常见的形状：

[ 物理页框号 PFN | 页内偏移 offset ]

偏移还是那个偏移，换的是页框号。

3）辅存地址

辅存不是一个统一的“地址格式”，要看介质：

• 磁盘：上层常见的是 LBA（逻辑块号）

• Flash：控制器内部维护逻辑页/逻辑块到物理页/物理块的映射

• 文件：还会再叠一层文件系统逻辑（文件偏移、inode 等）

关键纠偏：页表里通常不是“同时记录虚页号、实页号、页内地址”三样都齐全。更准确地说是：虚页号来自地址本身，页内偏移也来自地址本身，页表项里主要存页框号 + 有效位等控制信息。

1 页表是什么

页表就是一本“翻译簿”：虚拟页号 → 物理页框号。

程序发来虚拟地址，先拆出页号，用页号去页表里查，查到页框号后，再把页内偏移拼上去。

页表项常见内容作用
页框号 PFN告诉你这一页现在在主存哪一帧
有效位 valid表示该页是否在主存
访问位 / 脏位辅助替换、回写等管理
权限位控制可读 / 可写 / 可执行
别再把页表记成“三件套”：页表项通常不是“虚页号 + 实页号 + 页内地址”全写进去。
虚页号和页内偏移来自虚拟地址本身，页表项主要存的是页框号和控制信息。

2 地址转换怎么发生

命中时

1. CPU 发出虚拟地址。

2. MMU 先查 TLB（如果有）。

3. TLB / 页表给出 PFN。

4. PFN + offset → 物理地址。

缺页时

1. 页表项 valid = 0。

2. 触发缺页中断。

3. OS 去辅存找该页。

4. 调入主存，更新页表，再重启指令。

纠偏：你说的“实转虚”不是标准访存路径。硬件标准路径是虚拟 → 物理；反查“某个物理页对应哪个虚拟页”属于操作系统的管理问题，不是 CPU 每次访问都做的事。

3 快表 TLB 是什么

TLB = 快表 / 页表缓存。

它不是另一套地址体系，而是为了更快查页表，把最近用过的“虚页号 → 页框号”先缓存起来。

命中 直接拿到页框号，少走一次内存访问。

未命中 还得去页表里查，慢一点，但结果一样。

TLB 命中：虚拟地址 → TLB → 物理地址 TLB 未命中：虚拟地址 → 页表 → 物理地址

4 具有 TLB 和 Cache 的多级存储系统

这块最容易混，因为它其实有 两条不同的“快”：

• TLB：加速“地址翻译”

• Cache：加速“数据访问”

记忆法：TLB 管“去哪里找”；Cache 管“找到后先放哪儿快点用”。一个管地址，一个管数据。

1 3.6.1 虚拟存储器的基本概念

你可以先这样理解

虚拟存储器 = 程序看到的“更大、更连续”的地址空间，但这不等于真有那么多 RAM。

它的关键思想是：先假装大，再按需把真正需要的内容放进主存。

它解决什么问题

1. 程序能用看起来很大的连续空间。

2. 物理内存不足时，仍可运行大程序。

3. 进程之间彼此隔离。

虚拟地址空间 ≠ 物理内存大小
虚拟存储器 = 主存 + 辅存 共同支撑出来的“看起来很大”的地址空间
一句话模型

程序只管用 虚拟地址；MMU 把它翻成 物理地址；如果页不在内存，就去辅存里找，再换入主存。

2 3.6.2 页式虚拟存储器

页式的核心：把虚拟地址空间切成很多 大小相等 的页，把主存切成同样大小的页框（帧）。

地址一般拆成两部分：页号 VPN + 页内偏移 offset

重点：页式虚拟存储器里，页大小是固定的，所以转换时“页内偏移”直接原样保留，变的是页号对应的页框号。

3 3.6.3 段式虚拟存储器

段式不是按固定大小切，而是按 逻辑意义 切：代码段、数据段、堆段、栈段……

地址一般拆成：段号 + 段内偏移

4 3.6.4 段页式虚拟存储器

段页式 = 先按逻辑分段，再把每个段分页。它同时想要“逻辑好理解”和“页式好管理”。

第一步 段号找到段表项。

第二步 段表项里有该段的页表地址。

第三步 页号查页表，得到页框号。

第四步 页框号 + 页内偏移 → 物理地址。

它比页式多了一层表。

所以更灵活，但硬件/表项管理也更复杂。

// 逻辑路径 段号 → 段表 → 段内页表 → 页表 → 页框号 → 物理地址

5 3.6.5 虚拟存储器与 Cache 的比较

虚拟存储器

目标：扩大地址空间，让程序觉得内存很大。

关注：程序能不能跑、页是否在内存里。

缺页时：去辅存取数据。

Cache

目标：加速访问，让 CPU 少等主存。

关注：CPU 访问速度、命中率。

缺失时：去主存取数据。

项目虚拟存储器Cache

6 磁盘的地址是什么样的？

先说结论：现代操作系统通常不直接使用“磁道 + 扇区”的老式物理地址，而是用 LBA（逻辑块地址）。

磁盘内部当然仍然有磁道、扇区、柱面这些物理概念，但对上层软件来说，通常只看成一串连续编号的逻辑块。

你那句“磁盘是扇区、磁道，它的地址是什么样的？” 答案是：硬件内部有物理几何，软件上层多用逻辑块地址 LBA。你做虚拟存储器转换时，通常不会直接拿“磁道号”去参与页表计算。

7 主存的地址是什么样的？

主存（RAM）是这几层里最标准的“地址空间”之一。通常你可以把它理解成：一排可编址的存储单元。

但这里的“单元”不一定等于一个 bit，也不一定等于一个 word，要看机器采用什么编址方式。

常见理解

• 字节编址：一个地址对应 1 字节。

• 字编址：一个地址对应 1 个字。

• 教材里常重点讲 字节编址。

你卡住的地方

“存储阵列里一行是一个字”是内部组织；

“一个地址对应几个字节”是对外编址方式。

名词更像什么说明
存储体内部阵列电容 / 双稳态器排成网格这是物理实现
存储单元可被单独选中的最小编址对象可能是 1 字节，也可能更大
地址单元编号不是“存储在单元里的数据”

8 Flash 的地址是什么样的？

你对 Flash 的直觉已经很接近了：块（block）—页（page）—单元（cell） 这种层次关系确实是它的典型结构。

但要注意：Flash 的读写和擦除规则 跟 RAM 完全不同，所以“地址”也不能按 RAM 的方式想。

纠偏：你说“多个存储体、每个存储体内多个块、块里多个页”这个方向是对的。更准确地说，Flash 通常由 控制器把逻辑地址映射到物理页/物理块，不是程序直接按物理块硬写。

9 把你的困惑一次讲透

1. “如果考量不一样，转化就无法进行吗？” —— 不会。正是因为层次不同，才要有翻译器：页表、段表、MMU、FTL 都在做翻译。

2. “磁盘、主存、Flash 的地址为什么不一样？” —— 因为它们服务的对象不同：CPU 直接访问的是主存；磁盘和 Flash 通常是后备存储。

3. “磁道扇区是不是程序地址？” —— 通常不是。程序更常见的是 LBA、虚拟地址、物理地址这些抽象层地址。

4. “主存一行就是一个地址吗？” —— 要看编址方式。教材里常用字节编址，但内部阵列组织可以是按字、按块、按行设计。

5. “实转虚为什么矛盾？” —— 因为标准硬件路径只有虚拟 → 物理。反过来找“某个物理地址对应哪个虚拟地址”，那是操作系统的逆向映射问题，不是 CPU 访存的正常路径。

最后把总逻辑记成一句话：
程序看虚拟地址 → MMU 翻成主存物理地址 → 辅存按自己的规则保存数据 → 磁盘/Flash 还有自己独立的地址体系
