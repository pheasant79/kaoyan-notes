# 第4章 串

> **本章要解决的问题：** 在一段字符序列中寻找连续模式，怎样避免失配后重复比较？

<span style="color:#2563EB"><strong>一句话主线：</strong></span>
字符序列 → 串的基本操作 → 主串与模式串 → BF 逐起点比较 → KMP 复用已匹配信息。

[返回全书总览](00_全书总览.md)

## 先看结论

- <span style="color:#2563EB"><strong>必须掌握：</strong></span>串是字符组成的特殊线性表；子串要求连续，子序列不要求连续。
- <span style="color:#16A34A"><strong>必须掌握：</strong></span>BF 失配后换下一个起点；KMP 利用模式串的前后缀信息，主串指针不回退。
- <span style="color:#DC2626"><strong>必须掌握：</strong></span>`next`、`nextval` 的数值依赖下标和定义约定，不能脱离约定硬套表。
- <span style="color:#2563EB"><strong>必须掌握：</strong></span>BF 最坏 `O(nm)`，KMP 预处理后匹配可做到 `O(n+m)`。

## 知识主线

本章始终围绕一个问题：**模式串是否在主串中出现，以及它从哪里开始出现？**

1. 先明确字符序列、前缀、后缀和子串；
2. 再选择串的存储表示；
3. 最后比较失配后的处理方式。

<a id="string-basics"></a>
## 串的基本概念

- **串：** 由零个或多个字符组成的有限序列。
- **串长：** 串中字符的数量。
- **空串：** 不含任何字符，长度为 0。
- **空格串：** 含有一个或多个空格字符，长度大于 0。
- **子串：** 从原串中截取的连续字符段。
- **子序列：** 保持原有先后次序，但不要求连续。
- **前缀：** 从串首开始的子串。
- **后缀：** 到串尾结束的子串。
- **真前缀/真后缀：** 不包含串本身的前缀或后缀。

**短例子：** 对串 `abcab`，`cab` 是子串；`acb` 可以保持字符次序但不连续，因此只能算子序列，不是子串。

<a id="matching-objects"></a>
## 主串与模式串

- **主串 `T`：** 被搜索的字符序列，长度记为 `n`。
- **模式串 `P`：** 希望在主串中寻找的字符序列，长度记为 `m`。

匹配通常要返回模式串在主串中的起始位置；若不存在，则报告失败。

<a id="string-storage"></a>
## 串的存储

### 顺序存储

字符连续保存，便于按位置访问。

- 定长数组：容量固定，操作要注意越界或截断；
- 动态空间：可按需扩展，但扩容时可能重新分配和复制。

### 链式存储

字符或字符块通过链接组织。

- 访问某一位置通常要沿链接寻找；
- 每个结点需要链接空间；
- 按字符块存储可以降低每个字符都带链接的开销。

<a id="bf"></a>
## BF：朴素模式匹配

BF 从主串的每个候选起点开始，逐字符与模式串比较：

1. 当前字符相等，主串和模式串同时向后；
2. 发生失配，模式串回到开头；
3. 主串换到下一个候选起点；
4. 直到匹配成功或剩余长度不足。

优点是不需要预处理模式串；缺点是可能反复比较主串中的同一批字符。

<a id="kmp"></a>
## KMP：利用前后缀信息

KMP 的核心不是“跳过任意字符”，而是利用已经匹配的模式串前缀，判断失配后仍然可能保留多少匹配状态。

### 失配时发生什么

假设模式串前面一段已经匹配，当前字符失配。KMP 不让主串指针回退，而是把模式串状态回退到一个仍可能成立的相等真前缀位置。

### `next`

`next` 是失配处理的辅助表，记录模式串状态回退的位置或已匹配前缀长度，具体数值取决于教材约定。

### `nextval`

`nextval` 在 `next` 基础上进一步跳过“回退后仍会与当前字符失配”的状态，减少部分无意义比较。

<span style="color:#DC2626"><strong>注意：</strong></span>
不同教材可能采用从 0 或 1 开始的下标，也可能把 `next[j]` 定义为长度或下一次比较位置。计算表和套公式前，必须先确认同一套约定。

## 一般串操作

常见操作包括求长度、比较、连接、取子串、插入、删除和替换。

字典序比较不能只比较长度：先比较第一个不同字符；若一方是另一方的前缀，通常短串更小。

## 重要方法比较

| 比较项 | BF | KMP |
|---|---|---|
| 基本思想 | 每次失配后换下一个主串起点 | 利用模式串前后缀信息回退 |
| 主串指针 | 可能反复回退或重新比较 | 匹配过程中不回退 |
| 是否预处理模式串 | 不需要 | 需要计算 `next` 或 `nextval` |
| 最坏时间 | `O(nm)` | 预处理 `O(m)`，匹配 `O(n)` |
| 辅助空间 | `O(1)` | 通常 `O(m)` |
| 适合场景 | 实现简单、模式较短 | 需要稳定线性匹配，或重复使用模式串 |

<a id="complexity"></a>
## 性质与复杂度

设主串长度为 `n`，模式串长度为 `m`，单个字符访问按 `O(1)` 计：

- BF 最坏时间 `O(nm)`，辅助空间 `O(1)`；
- KMP 预处理 `O(m)`，匹配 `O(n)`，合计 `O(n+m)`；
- KMP 辅助表空间通常为 `O(m)`；
- `nextval` 改善比较过程，但不改变上述渐进数量级。

<a id="boundaries"></a>
## 易错与边界

- 子串必须连续；子序列只要求相对次序不变。
- `next` 数组是 KMP 的辅助信息，不是链表中的 `next` 指针。
- KMP 的线性复杂度依赖正确的前后缀回退机制，不是“用了表就一定线性”。
- 本章处理字符序列匹配；第7章处理查找表中关键字的定位。
- 模式匹配和查找都属于定位问题，但数据对象和算法机制不同。
