用途：复习时定位名词、回顾关系、比较方法。八章沿用已确认的教材边界；章内按知识关系组织，每章只有一个完整树状块。

**归位规则**：缩进表示“属于哪个问题或分类”，关系词区分“是一种、实现为、用于、依赖”。箭头只表示具体步骤或明确标注的学习路线。“主归属”指本书集中展开的位置，不表示一个概念只能用于这一章。

## 第1章 绪论：先分清对象、规范、实现与评价

```markdown
绪论
本章问题：用什么概念描述数据，怎样说明“能做什么、如何做、代价多大”？
├─ 1. 核心对象：被处理的数据与处理方法
│  ├─ 数据元素：通常作为一个整体处理的基本单位
│  │  └─ 数据项：构成元素的属性；在当前抽象层次上不可再分
│  ├─ 数据对象：具有相同性质的数据元素集合
│  │  └─ 例：学生记录是元素；学号、姓名是数据项；学生记录集合是对象
│  ├─ 数据结构：相互之间存在特定关系的数据元素集合
│  └─ 数据类型：值的集合，以及定义在这些值上的操作集合
├─ 2. 逻辑关系与规范：描述数据，不预设具体存放方式
│  ├─ 按元素间关系分类
│  │  ├─ 集合：除同属一个集合外，不规定其他关系
│  │  ├─ 线性结构：一对一的前后关系
│  │  ├─ 树形结构：一对多的层次关系
│  │  └─ 图状结构：一般的多对多关系
│  ├─ 逻辑结构、存储结构、数据运算是观察数据结构的三个方面
│  └─ 抽象数据类型 ADT〔规范〕
│     ├─ 规定数据对象、逻辑关系和允许的操作
│     └─ 说明操作的输入、输出和效果，不指定数组或指针等实现
├─ 3. 存储实现：在计算机中表示元素和关系
│  ├─ 顺序存储：用连续单元及位置规则表示关系
│  │  └─ 定位方便；改变位置关系时可能需要移动元素
│  ├─ 链式存储：用链接记录关系，不要求相邻结点地址连续
│  │  └─ 调整关系较灵活；要付出链接空间和沿链接访问的代价
│  ├─ 索引存储：在记录之外建立“关键字等信息—位置”索引
│  │  └─ 帮助定位；索引本身需要空间与维护
│  └─ 散列存储：按关键字计算表内位置，并处理冲突
│     └─ 等值定位通常较快；性能受散列函数、装填程度和冲突影响
├─ 4. 操作与算法：区分目标和实现步骤
│  ├─ 数据运算〔做什么〕：访问、插入、删除、查找、遍历等
│  ├─ 算法〔怎么做〕：在选定表示下，用有限步骤完成任务
│  ├─ 算法的五个特征：有穷性、确定性、可行性、输入、输出
│  │  └─ 输入可为零个或多个；输出至少一个；有穷性要求有限步结束
│  └─ 设计要求：正确、可读、健壮，并兼顾时间与空间效率
├─ 5. 性质与复杂度：先确定规模和情况，再判断增长阶
│  ├─ 时间复杂度：基本操作次数随输入规模增长的数量级
│  │  ├─ 顺序执行通常取主导项；循环次数要看变量如何变化
│  │  └─ 嵌套循环不自动等于 O(n²)，递归也不能只看代码行数
│  ├─ 空间复杂度：本文采用辅助空间口径，不计输入本身，计递归栈
│  ├─ 最好、平均、最坏：区分同一规模下的不同输入情况
│  ├─ O 是渐进上界；Ω 是下界；Θ 是紧确界
│  │  └─ 它们与最好/平均/最坏是两套维度，O 不等于最坏情况
│  └─ 常见增长阶：O(1)、O(log n)、O(n)、O(n log n)、O(n²)、O(2^n)
└─ 6. 边界与关联：不要把不同层次写成上下级
   ├─ ADT 是功能规范；存储结构是表示；算法是操作的实现方法
   ├─ 一种逻辑结构可以有多种存储实现；一种存储方式可用于多种结构
   ├─ 顺序、链式、索引、散列也可组合使用，不是四个绝不相交的盒子
   ├─ 具体线性表实现见第2章；索引与散列查找机制见第7章
   └─ 实现关联备注：struct、typedef、指针是语言工具，不是新的逻辑结构
```

## 第2章 线性表：关系不变，实现与操作代价不同

```markdown
线性表
本章问题：怎样表示一条有先后次序的序列，并有效访问、插入和删除元素？
├─ 1. 核心对象：线性表〔逻辑模型及操作规范〕
│  ├─ 同类数据元素构成的有限序列，长度 n 可以为 0
│  └─ “有顺序”指元素有先后位置，不代表关键字已经按大小排序
├─ 2. 逻辑关系：前驱、后继和位序
│  ├─ 非空表中，除首元素外，每个元素恰有一个直接前驱
│  ├─ 除末元素外，每个元素恰有一个直接后继
│  └─ 位序是逻辑位置；数组下标是实现中的编号，二者起点可能不同
├─ 3. 存储实现：顺序表与链表是并列选择
│  ├─ 顺序表〔顺序实现〕
│  │  ├─ 逻辑相邻元素占据连续存储位置，地址可由首地址和偏移算出
│  │  ├─ 固定容量：预先安排空间；容量受限
│  │  └─ 动态容量：运行时申请或扩展连续空间；扩容可能搬迁已有元素
│  └─ 链表〔链式实现〕
│     ├─ 用结点保存数据和链接，物理相邻不是必要条件
│     ├─ 按链接方向分：单链 / 双链
│     │  └─ 双链增加前驱链接，方便反向访问，但多占空间、多维护链接
│     ├─ 按首尾连接分：非循环 / 循环
│     │  └─ 循环形式便于环形处理；结束条件不能照搬“遇空指针结束”
│     ├─ 按链接表示分：地址指针 / 数组下标（游标）
│     │  └─ 静态链表用游标表示后继，不按相邻数组位置表示前后关系
│     └─ 这些分类可以组合：例如双向循环链表，不是四选一
├─ 4. 基本操作：同一接口可以有不同实现
│  ├─ 初始化、判空、求长度、遍历、销毁
│  ├─ 按位访问：给位置取元素；按值查找：比较内容以定位元素
│  ├─ 顺序表插入：先从后向前移动后缀，再放入新元素
│  ├─ 顺序表删除：移走目标，再从前向后填补空位
│  ├─ 单链表插入：先让新结点接上后继，再修改前驱链接
│  ├─ 单链表删除：让前驱跨过目标；需要时回收目标结点空间
│  └─ 建链方法：头插通常逆置输入次序；维护尾指针的尾插保留输入次序
├─ 5. 性质与代价：必须把复杂度绑定到具体操作
│  ├─ 顺序表按位访问 O(1)；无序表按值顺序查找最坏 O(n)
│  ├─ 顺序表一般位置插入/删除平均、最坏 O(n)
│  │  ├─ 长度 n、位序从 1 起：插入第 i 位移动 n-i+1 个元素
│  │  └─ 删除第 i 位移动 n-i 个；尾部操作在无需扩容时可为 O(1)
│  ├─ 链表按位访问、按值顺序查找最坏 O(n)
│  ├─ 单链表已知前驱后，插入或删除其后继只需 O(1) 链接修改
│  │  └─ 只知道待删结点，不等于知道前驱；寻找前驱仍可能 O(n)
│  ├─ 双链表已知待删结点，可借前驱链接在 O(1) 时间摘除它
│  └─ 选择要比较完整任务：定位 + 修改；不能只凭“插删多”断言链表更好
└─ 6. 边界与关联：实现名词放回实现层
   ├─ 顺序表不是“已排序的表”；动态分配也不等于链式存储
   ├─ 静态链表的底层可连续，但表示线性关系靠游标，因此仍是链式实现
   ├─ 实现关联备注：头指针保存入口地址；头结点是可选辅助结点
   │  └─ 首元结点才存第一个有效元素；头结点用于统一边界处理
   ├─ 实现关联备注：InitList 是教材操作名，LinkList 常是指针类型别名
   └─ 受限操作形式见第3章；有序表上的折半查找集中在第7章
```

## 第3章 栈、队列和数组：操作约束与存储映射是两条分支

```markdown
栈、队列和数组
本章问题：限制操作位置会带来什么用途；多维下标如何映射到存储位置？
├─ 1. 核心对象：两条并列研究分支
│  ├─ 操作受限的线性结构：栈、普通队列、双端队列
│  └─ 按下标组织的数据：一维/多维数组，以及矩阵的存储表示
├─ 2. 逻辑关系与操作约束
│  ├─ 栈：同一端入栈、出栈，后进先出 LIFO
│  ├─ 普通队列：队尾入队、队头出队，先进先出 FIFO
│  ├─ 双端队列：两端可插入、删除，不再保证普通队列的 FIFO 次序
│  │  └─ 输入受限、输出受限是对双端操作的进一步约束
│  └─ 数组：每个元素由一组合法下标定位；下标顺序不代表元素值有序
├─ 3. 存储实现：规则与底层实现分开
│  ├─ 栈的实现
│  │  ├─ 顺序栈：数组 + 栈顶位置；要处理容量边界
│  │  │  └─ 共享栈：两个顺序栈从同一数组两端向中间使用空间
│  │  └─ 链栈：在链表一端入栈、出栈，避免为每次操作寻找尾部
│  ├─ 普通队列的实现
│  │  ├─ 顺序队列：用数组保存队列元素
│  │  │  ├─ 非循环形式：下标单向移动，可能留下无法复用的前部空位
│  │  │  └─ 循环队列：下标按容量取模，复用这些空位，避免“假溢出”
│  │  └─ 链队列：通常维护队头、队尾，入队和出队都不必全表扫描
│  ├─ 数组的顺序表示：行优先或列优先，将多维下标线性化
│  │  ├─ 设 r 行 c 列、下标从 0 起、元素宽 w、首地址 B
│  │  ├─ 行优先 A[i][j] 地址 = B + (i*c+j)*w
│  │  └─ 列优先 A[i][j] 地址 = B + (j*r+i)*w
│  └─ 矩阵压缩存储：压缩规则由数据特点决定，两种特点可以重合
│     ├─ 利用规律：对称、三角、带状（如三对角）矩阵
│     │  └─ 只存必要区域，按规则换算下标；三角外的公共常量另行保存
│     └─ 利用稀疏性：保存非零值及其行列位置，如三元组表
│        └─ 空间随非零元数增长，但不能再直接套用完整数组地址公式
├─ 4. 操作与应用：操作约束为什么有用
│  ├─ 栈的基本操作：入栈、出栈、读栈顶、判空/满
│  ├─ 括号匹配：未配对左括号入栈，右括号与栈顶配对，结束检查空栈
│  ├─ 表达式处理：栈保存运算符或操作数，按优先级及操作数次序处理
│  ├─ 递归执行：调用栈保存返回位置和局部状态，递归需要终止条件
│  ├─ 队列基本操作：入队、出队、读队头、判空/满
│  └─ 队列用于等待服务和按层访问；具体树/图遍历分别见第5、6章
├─ 5. 性质与代价：先声明实现约定
│  ├─ 常规栈、队列单次入/出操作 O(1)，不含扩容等额外开销
│  ├─ 长度 n 的括号匹配：时间 O(n)，最坏辅助空间 O(n)
│  ├─ 递归的辅助空间与最大调用深度有关，不只取决于函数个数
│  ├─ 循环队列采用“容量 N，留一个空位”的约定时
│  │  ├─ front 指队头，rear 指下一个可入队位置
│  │  ├─ 空：front == rear；满：(rear+1) mod N == front
│  │  └─ 元素数：(rear-front+N) mod N；最多存 N-1 个
│  └─ 对称 n 阶矩阵独立元素 n(n+1)/2；稀疏三元组空间 O(t)，t 为非零元数
└─ 6. 边界与关联：不要强接成“栈变队列、队列变数组”
   ├─ 顺序/链式是实现维度；LIFO/FIFO/双端是操作约束维度
   ├─ 循环队列不是循环链表；都称“循环”，但实现对象和办法不同
   ├─ 使用计数器或标志判满时，不能照搬“留一个空位”的判定式
   ├─ 数组可用于实现顺序表、栈、堆、邻接矩阵，不专属于一种逻辑关系
   └─ 第6章 BFS 使用队列，DFS 使用显式栈或递归；这里不重复展开算法
```

## 第4章 串：把匹配任务与失配处理联系起来

```markdown
串
本章问题：在一段字符序列中找连续子串，怎样避免重复比较？
├─ 1. 核心对象：字符序列及匹配双方
│  ├─ 串：由零个或多个字符组成的有限序列；长度指字符数
│  ├─ 空串长度为 0；空格串含一个或多个空格字符，长度大于 0
│  └─ 主串 T 是搜索范围；模式串 P 是本次希望找到的字符序列
├─ 2. 逻辑关系：串是字符构成的线性序列
│  ├─ 子串必须连续；子序列只保持先后次序，不要求连续
│  ├─ 前缀从串首开始，后缀到串尾结束；“真”前后缀不含串本身
│  └─ 相等真前后缀提供“失配后哪些已知匹配仍可复用”的依据
├─ 3. 存储实现：保存字符，并记录长度或结束边界
│  ├─ 顺序存储：字符连续，便于按位置访问
│  │  ├─ 定长数组：容量固定，操作必须检查越界或截断
│  │  └─ 堆分配：按需申请空间，增长时可能重新分配与复制
│  └─ 链式存储：按字符或字符块链接，访问某一位置一般要沿链寻找
│     └─ 链接占额外空间；按块存储可减少每个字符的链接开销
├─ 4. 操作与算法：一般串操作和模式匹配分开
│  ├─ 一般操作：求长、比较、连接、取子串、插入、删除、替换
│  │  └─ 按字典序比较不是只比较长度，要看首个不同字符或前缀关系
│  └─ 模式匹配〔在主串中寻找模式串的出现位置〕
│     ├─ BF / 朴素匹配
│     │  ├─ 思想：从候选起点逐字符比较；失配后换下一个起点重试
│     │  └─ 不需要模式串预处理，但可能反复比较同一批字符
│     └─ KMP
│        ├─ 思想：利用模式串的前后缀信息，失配后保留仍成立的匹配
│        ├─ 只调整模式串的匹配状态，主串扫描位置不回退
│        ├─ next〔辅助表〕：给出失配时模式串状态的回退位置
│        └─ nextval〔优化表〕：跳过必然再次失败的相同字符比较
├─ 5. 性质与代价：说明 n、m 及表的约定
│  ├─ 设主串长 n、模式串长 m，比较/访问单个字符按 O(1) 计
│  ├─ BF：最坏时间 O(nm)，辅助空间 O(1)
│  ├─ KMP：预处理 O(m)，匹配 O(n)，合计 O(n+m)，辅助空间 O(m)
│  ├─ nextval 改善部分重复比较，不改变 KMP 的上述渐进数量级
│  └─ 下标从 0/1 起、next 表示长度/下次位置等约定会改变表中数值
└─ 6. 边界与关联：辅助信息不等于另一种数据结构分类
   ├─ next 数组属于 KMP 的辅助机制，不是链表 next 指针的同一对象
   ├─ 计算或套用 next/nextval 前，必须使用同一套下标和失配规则
   ├─ 本章处理字符序列匹配；第7章集中处理查找表中的关键字定位
   └─ 二者都属于查找任务；这里分章是为了区分数据对象和算法机制
```

## 第5章 树与二叉树：把形状、表示、访问和应用分开

```markdown
树与二叉树
本章问题：层次关系怎样表示和访问，又怎样服务编码与集合管理？
├─ 1. 核心对象：树、二叉树、森林
│  ├─ 树：根及递归分解的子树构成层次；非根结点恰有一个双亲
│  ├─ 森林：若干棵互不相交的树的集合
│  └─ 二叉树：空树，或一个根与有明确左右位置的两棵二叉子树
├─ 2. 逻辑关系与形态：结点之间是什么关系
│  ├─ 亲缘关系：双亲、孩子、兄弟、祖先、后代
│  ├─ 结点的度是孩子数；树的度是各结点度的最大值
│  ├─ 层次/深度、高度、路径长度必须先统一根和计数约定
│  ├─ 二叉树的左右位置不能省：只有一个孩子也要区分左孩子或右孩子
│  └─ 按二叉树形状区分
│     ├─ 满二叉树：本文按国内教材口径，各层结点都达到最大数量
│     └─ 完全二叉树：除最后一层外均满，最后一层从左到右连续排列
├─ 3. 存储实现：分别看一般树和二叉树
│  ├─ 一般树
│  │  ├─ 双亲表示：每个结点记双亲位置，找双亲方便，找孩子需另行组织
│  │  ├─ 孩子表示：组织每个结点的孩子，枚举孩子方便
│  │  └─ 孩子-兄弟表示：首孩子链接 + 下一兄弟链接，统一成二叉链式形式
│  ├─ 二叉树
│  │  ├─ 顺序表示：按完全二叉树位置编号，形状稀疏时会留下空位
│  │  │  └─ 编号从 1 起：孩子位置 2i、2i+1；双亲 floor(i/2)，须检查是否存在
│  │  └─ 二叉链表：每个结点记录左右孩子链接，形状灵活，链接占空间
│  └─ 线索二叉树〔存储增强〕
│     └─ 按一种遍历次序，用空孩子链接保存前驱/后继，并用标志区分线索
├─ 4. 操作与算法：访问、转换、应用不是同一类名词
│  ├─ 二叉树遍历〔访问算法〕
│  │  ├─ 先序：根、左、右；中序：左、根、右；后序：左、右、根
│  │  ├─ 深度优先遍历可递归或使用显式栈；层序按层使用队列
│  │  └─ 线索化建立访问关联，按线索遍历时不能把线索误当孩子
│  ├─ 一般树与森林
│  │  ├─ 一般树：先根、后根遍历；森林：先序、中序遍历
│  │  ├─ 孩子-兄弟转换：左链接对应孩子、右链接对应兄弟，不是保留原形状
│  │  └─ 树先根/森林先序对应转换后二叉树先序；树后根/森林中序对应二叉树中序
│  ├─ 由遍历序列恢复二叉树
│  │  └─ 结点标识互异时，先序+中序或后序+中序可唯一确定；先序+后序一般不能
│  ├─ 哈夫曼树与编码〔最优前缀编码应用〕
│  │  ├─ 给定非负叶权，反复合并当前权值最小的两棵树，直到只剩一棵
│  │  ├─ 使叶结点的带权路径长度 WPL 最小；左右边标 0/1 得到前缀编码
│  │  └─ 等权选择和左右安排可能不同，因此最优树/编码不一定唯一
│  └─ 并查集〔不相交集合的管理结构〕
│     ├─ 用双亲森林表示集合：根是代表元，Find 找代表，Union 合并不同集合
│     ├─ 按秩/大小合并控制高度，路径压缩使后续查找更短
│     └─ 它不要求是二叉树；用于判断集合是否相同，而不是按大小搜索关键字
├─ 5. 性质与代价：以下约定根为第 1 层，高度按层数计
│  ├─ 非空树 n 个结点有 n-1 条边；各结点孩子数之和为 n-1
│  ├─ 非空二叉树：叶数 n0 = 度为2的结点数 n2 + 1
│  ├─ 第 i 层最多 2^(i-1) 个结点；高度 h 最多 2^h-1 个结点
│  ├─ n 个结点的完全二叉树高度为 floor(log2 n)+1
│  ├─ 各遍历访问所有结点的时间 O(n)；递归栈 O(h)，层序队列最坏 O(n)
│  ├─ WPL = sum(叶权 * 根到该叶的边数)，不要把非叶结点也计入叶权和
│  ├─ 哈夫曼构造若用二叉堆选择最小权：O(n log n) 时间、O(n) 空间，堆见第8章
│  └─ 并查集同时用按秩/大小合并与路径压缩：每次操作摊还 O(alpha(n))
│     └─ alpha(n) 增长极慢，但不能写成任意单次操作最坏 O(1)
└─ 6. 边界与关联：形态、查找规则、应用目标各有位置
   ├─ 二叉树不只是“度不超过2的普通树”：左右子树的位置是定义的一部分
   ├─ 一般二叉树的中序序列不必按关键字有序；有序性来自第7章 BST 的约束
   ├─ BST、AVL、红黑树、B/B+树集中见第7章；本章不重复查找操作
   ├─ 二叉堆集中见第8章，借用本章完全二叉树的形状性质
   └─ 并查集用于第6章 Kruskal 判环；哈夫曼思想关联第8章最佳归并树
```

## 第6章 图：先认问题目标，再选择算法

```markdown
图
本章问题：怎样表示一般关联关系，并分别解决遍历、连通、路径和依赖问题？
├─ 1. 核心对象：G=(V,E)，顶点集合与边集合
│  ├─ 顶点表示对象；边表示对象之间的关系；边权表示距离、费用等
│  └─ 以下用 v 表示顶点数、e 表示边数，不把所有规模都笼统写成 n
├─ 2. 逻辑关系：分类依据分开
│  ├─ 方向：无向边 / 有向弧；度、入度、出度据此定义
│  ├─ 权：无权 / 带权；“有向”并不等于“有权”
│  ├─ 路径、回路：研究可达及是否绕回；DAG 指有向无环图
│  ├─ 无向图：连通分量是极大的连通子图
│  └─ 有向图：强连通要求顶点相互可达，不能用单向可达直接代替
├─ 3. 存储实现：关注要做的访问操作
│  ├─ 邻接矩阵
│  │  ├─ 空间 O(v²)，判断一条边是否存在 O(1)，枚举一顶点邻接点 O(v)
│  │  └─ 适合较稠密图；带权矩阵要区分“零权边”和“不存在的边”
│  ├─ 邻接表
│  │  ├─ 空间 O(v+e)，枚举某顶点邻接点只需遍历相应表
│  │  └─ 适合稀疏图；查任意指定边不保证 O(1)；无向边通常记录两次
│  ├─ 十字链表：有向图的一条弧结点同时接入弧尾出边链和弧头入边链
│  └─ 邻接多重表：无向图的一条边结点同时接入两端点的关联边链
├─ 4. 操作与算法：每组对应一个任务
│  ├─ 访问全部顶点〔遍历〕
│  │  ├─ BFS：用队列逐层扩展；还可求无权/等正权图的最少边数路径
│  │  ├─ DFS：沿未访问邻接点深入，用递归或显式栈回溯
│  │  └─ 从一点不能访问全图时，再从未访问顶点启动，得到遍历森林
│  ├─ 最小生成树〔无向带权连通图，连接全部顶点且总边权最小〕
│  │  ├─ Prim：从已有顶点集合向外，反复选跨边界的最小权边
│  │  ├─ Kruskal：按权递增考虑边，不成环才接纳；并查集见第5章
│  │  └─ 不连通图不能生成覆盖全图的一棵树，可讨论最小生成森林
│  ├─ 最短路径〔使起终点之间的路径代价最小〕
│  │  ├─ Dijkstra：单源、边权非负；反复确定当前最近顶点，再松弛相邻边
│  │  └─ Floyd：依次允许各顶点作中间点，更新所有点对距离
│  │     └─ 可有负权边；要求不存在使所求最短路无下界的负权回路
│  └─ 依赖与工期〔基于有向无环关系〕
│     ├─ AOV网 + 拓扑排序
│     │  ├─ 顶点是活动、弧是先后依赖；反复输出入度为0的顶点并删除出边
│     │  └─ 未输出全部顶点就无法继续，说明有环；合法序列可能不唯一
│     └─ AOE网 + 关键路径
│        ├─ 边是带工期的活动、顶点是事件；边权按非负工期理解
│        ├─ 采用统一源、汇；多源或多汇可通过零工期虚活动连接起来
│        ├─ 按拓扑序求事件最早时间，按逆拓扑序求最迟时间，再算活动余量
│        └─ 最早与最迟开始时间相等的活动是关键活动；关键路径可能多条
├─ 5. 性质与代价：下列采用常见教材实现
│  ├─ 无向图各顶点度之和 2e；有向图总入度 = 总出度 = e
│  ├─ BFS/DFS：邻接表时间 O(v+e)，邻接矩阵时间 O(v²)，辅助空间 O(v)
│  ├─ Prim 的矩阵实现 O(v²)；Kruskal 的排序实现通常 O(e log e)
│  ├─ Dijkstra 的朴素实现 O(v²)；Floyd 时间 O(v³)、距离表空间 O(v²)
│  ├─ 邻接表上的入度式拓扑排序、关键路径分析均可为 O(v+e)
│  └─ AOE工程工期由源到汇的最长路径决定，不是边数最多的路径
└─ 6. 边界与关联：相似名字不代表同一任务
   ├─ 生成树不一定是最小生成树；最小生成树不保证任意两点间路径最短
   ├─ BFS既是遍历方法，也能解特定最短路问题，不能说它“不是最短路算法”
   ├─ 一次普通DFS/BFS不能直接把有向图分成全部强连通分量
   ├─ 拓扑排序依据依赖约束，不是第8章按关键字大小排序
   └─ 缩短一条关键路径上的活动未必缩短总工期，还要看其他关键路径
```

## 第7章 查找：数据怎样组织，决定能怎样找

```markdown
查找
本章问题：在什么组织和约束下，怎样定位记录，并兼顾更新代价？
├─ 1. 核心对象：查找表、记录、关键字
│  ├─ 查找表：供查找的记录集合；关键字：用于识别或比较记录的信息
│  ├─ 查找成功：找到目标；查找失败：确认目标不存在
│  └─ ASL〔平均查找长度〕：按各情况概率加权的平均比较/探测次数
├─ 2. 逻辑关系与任务约束
│  ├─ 静态/动态：是否还要插入、删除；这是使用需求，不是唯一算法分类
│  ├─ 有序/无序：关键字是否有可利用的次序；不是地址是否连续
│  ├─ 等值/范围：只找一个关键字，还是还要找某一区间的记录
│  └─ 内存/外存：代价重在比较次数，还是还要重点减少块读写
├─ 3. 数据组织：同一“查找”目标可使用不同结构
│  ├─ 线性表或分块索引：表的具体存储见第2章；索引先缩小搜索范围
│  ├─ 树形查找结构
│  │  ├─ 二叉查找树 BST：本文按关键字互异描述，左子树小于根、右子树大于根
│  │  │  ├─ 普通BST：没有额外平衡约束，形状依赖插入、删除过程
│  │  │  ├─ AVL：每个结点左右子树高度差绝对值不超过1，用旋转维护
│  │  │  └─ 红黑树：结点红/黑，根和NIL叶为黑，红结点无红孩子
│  │  │     └─ 从同一结点到各后代NIL的黑结点数相同，用变色和旋转维护
│  │  └─ 多路平衡查找树：B树、B+树，典型用途是外存索引
│  │     ├─ B树：结点内关键字有序，区间对应孩子，记录可关联内部和叶结点
│  │     │  └─ 分裂、合并或借关键字维持占用限制，所有叶结点在同一层
│  │     └─ B+树：内部结点作导航，全部记录在叶层，叶层按序相连
│  │        └─ 多路降低树高；叶链便于范围访问，但更新也要维护平衡与占用
│  └─ 散列表：关键字经H映射到槽位/桶，再配合冲突处理
│     ├─ 开放定址：冲突后按探测序列在表内寻找位置
│     └─ 链地址：同桶记录用链表等结构组织，不是直接覆盖旧记录
├─ 4. 操作与算法：将方法和前提绑定
│  ├─ 顺序查找：逐条比较；不要求有序，可用于顺序表或链表
│  ├─ 折半查找：有序且支持快速随机访问；比较中点，保留可能含目标的一半
│  ├─ 分块查找：块间有序、块内可无序；先查索引定位块，再查块内
│  ├─ 树形查找：按关键字范围沿分支下降；插删后维护各自结构约束
│  │  ├─ 普通BST插入定位新叶；删除双孩子结点可用中序前驱/后继替代
│  │  ├─ AVL修复局部失衡；LL/RR单旋，LR/RL双旋，保持中序有序
│  │  └─ 红黑树放宽高度约束；B/B+树用分裂、借位、合并处理占用变化
│  └─ 散列查找：计算桶位置，再沿相同探测规则或冲突链检查目标
│     ├─ 装填因子 alpha = 记录数/桶或槽位数；开放定址与链地址的限制不同
│     └─ 开放定址删除通常要保留删除标记，不能把探测链误截断成“从未使用”
├─ 5. 性质与代价：平均与最坏分清，CPU操作与I/O分清
│  ├─ ASL = sum(概率 * 比较次数)；成功、失败通常要分别计算
│  ├─ 顺序查找最坏 O(n)；迭代折半查找 O(log n) 时间、O(1) 辅助空间
│  ├─ b块、每块约s条时：索引顺序查找 O(b+s)，索引折半 O(log b+s)
│  ├─ 普通BST查找/插入/删除 O(h)，h为树高；有序插入等可能使h退化到n
│  ├─ AVL、红黑树把树高控制在 O(log n)，相关基本操作最坏 O(log n)
│  ├─ m阶B树中，m按最多孩子数计；非根内部结点至少ceil(m/2)个孩子
│  │  └─ 非叶根至少2个孩子；k个孩子对应k-1个关键字，不要和其他阶数约定混用
│  ├─ B/B+树查找所需块访问主要随树高增长；不能只看结点内比较次数
│  └─ 良好散列且装填受控时平均查找可达 O(1)，最坏仍可退化为 O(n)
└─ 6. 边界与关联：结构类别和应用场景不是同一分类维度
   ├─ B/B+树既是树形查找结构，也常用于外存；“外存”不是树形之外的新逻辑类别
   ├─ AVL是更严格平衡的BST；红黑树并不要求各结点高度差不超过1
   ├─ NIL叶是约定的空叶，不是说每个存实际数据的叶结点都必须为黑
   ├─ 散列地址是表内位置/桶号，不是把关键字直接变成任意硬件物理地址
   ├─ 查找目标是定位，并不要求排序；某些查找结构会在操作时调整内部组织
   └─ 树的通用性质见第5章；建立有序数据的排序算法见第8章
```

## 第8章 排序：按机制分类，再比较前提与代价

```markdown
排序
本章问题：怎样按关键字组织记录次序，哪种方法适合当前数据和存储条件？
├─ 1. 核心对象：待排序记录及排序关键字
│  ├─ 通常要求关键字非递减或非递增；移动的是完整记录或其引用
│  └─ 稳定性：相等关键字记录在排序前后的相对次序是否保持
├─ 2. 任务分类：两种分类依据不要混在同一级
│  ├─ 按数据能否全部在内存处理：内部排序 / 外部排序
│  └─ 按获得次序的机制：比较排序 / 非比较排序
│     ├─ 比较排序再按思想分：插入、交换、选择、归并
│     └─ 非比较排序利用关键字的位或值域信息，例如基数排序
├─ 3. 关键存储组织：服务于算法，不是另外一种排序目标
│  ├─ 数组：便于定位、交换；链式表示可改变某些算法的移动与空间代价
│  ├─ 二叉堆〔结构，集中在本章学习〕
│  │  ├─ 完全二叉树形状 + 父结点不小于孩子（大根堆）或不大于孩子（小根堆）
│  │  ├─ 常用数组表示；根是全局极值，但左右子树之间不要求整体有序
│  │  └─ 常用来实现优先队列：按优先级取极值，而不按到达次序取元素
│  └─ 外部归并段：外存中已经局部有序的记录段，用输入/输出缓冲分批处理
├─ 4. 操作与算法：每种名字对应一种主要机制
│  ├─ 内部排序常见算法
│  │  ├─ 比较排序
│  │  │  ├─ 插入类
│  │  │  │  ├─ 直接插入：把下一条记录插进已有有序前缀，移动比它大的记录
│  │  │  │  ├─ 折半插入：在有序前缀中折半找位置，后续移动仍然存在
│  │  │  │  └─ 希尔：按增量分组插入排序，逐步缩小增量，最后增量为1
│  │  │  ├─ 交换类
│  │  │  │  ├─ 冒泡：相邻逆序就交换，一趟使一个极值到位
│  │  │  │  └─ 快速：选基准划分，使两侧满足大小关系，再分别递归处理
│  │  │  ├─ 选择类
│  │  │  │  ├─ 简单选择：扫描未排序部分选极值，与边界记录交换
│  │  │  │  └─ 堆排序：建立大根堆，堆顶与末项交换，缩小堆并恢复堆序
│  │  │  └─ 二路归并：把两个有序段合为一段，递归拆分或自底向上扩大段长
│  │  └─ 非比较排序
│  │     ├─ 基数排序：关键字可拆为有限位；按位稳定分配、收集
│  │     │  └─ 常见LSD从低位到高位，各趟稳定才能保留已经形成的低位次序
│  │     └─ 计数排序〔所核对出版社目录带星号〕：按有限值域计数，累计后安排输出位置
│  └─ 外部排序〔教材主干是外部归并，不是另一种普通内部排序〕
│     ├─ 基本过程：生成初始归并段 → 多路归并 → 必要时继续归并
│     ├─ 置换-选择：用工作区反复选可接续本段的最小记录，不能接续的留到下一段
│     │  └─ 可产生长于工作区的归并段，长度取决于输入，不是恒为内存容量两倍
│     ├─ 败者树：维护各归并段当前记录的比较结果，快速选出下一条输出记录
│     └─ 最佳归并树：根据段长安排合并次序，使归并读写总量尽量小
│        └─ 对应带权路径长度思想；k路构造必要时补零长度虚段，不是单纯减少合并次数
├─ 5. 性质与复杂度：按常见数组实现；n为记录数，空间指辅助空间
│  ├─ 直接插入：最好O(n)，平均/最坏O(n²)；空间O(1)；稳定
│  ├─ 折半插入：比较O(n log n)，移动最坏O(n²)；空间O(1)；稳定
│  ├─ 希尔：时间依赖增量序列，不能笼统写成固定O(n log n)；空间O(1)；不稳定
│  ├─ 冒泡：带提前结束时最好O(n)，平均/最坏O(n²)；空间O(1)；稳定
│  ├─ 快速：平均O(n log n)，最坏O(n²)；常规递归栈平均O(log n)、最坏O(n)；不稳定
│  ├─ 简单选择：比较次数为Θ(n²)；空间O(1)；通常不稳定
│  ├─ 堆排序：建堆O(n)，整体最坏O(n log n)；迭代调整空间O(1)；不稳定
│  ├─ 二路归并：时间O(n log n)，数组辅助空间O(n)；相等时先取左段可稳定
│  ├─ 基数：d位、每位r种取值时，时间O(d(n+r))；常见实现空间O(n+r)；各趟须稳定
│  ├─ 稳定计数排序：值域大小K时，时间与辅助空间O(n+K)；值域过大不合适
│  └─ 外部归并：败者树更新的O(log k)是每条记录的CPU代价，还须计算I/O
│     └─ 逐趟k路归并r个初始段约需ceil(log_k r)趟，每趟读写N个磁盘块约2N次块I/O
└─ 6. 边界、选型与补充：不设一个放之四海皆准的“最快”
   ├─ 近乎有序或规模小：直接插入常合适；要一般平均效率：可考虑快速
   ├─ 需要最坏O(n log n)且辅助空间小：考虑堆排序，但它并不保持相等记录次序
   ├─ 要求稳定：核对具体实现；选择归并等稳定算法，还要接受其空间代价
   ├─ 一般比较排序最坏至少需Ω(n log n)次比较，不代表每一种输入都需这么多
   │  └─ 该比较下界不约束利用位或值域的非比较排序
   ├─ 二叉堆借用第5章完全二叉树性质，不等于第7章BST，也不等于内存中的“堆区”
   ├─ 最佳归并与第5章哈夫曼思想关联；上面逐趟I/O估算不含生成初始段
   │  └─ 不等长段的最佳归并要按各段实际参与的归并计算，不能机械套趟数公式
   └─ 计数排序按出版社目录保留并标星号；没有据此断言它属于必考或不考
```

| 对照 | 判断关键 |
|---|---|
| 逻辑结构 / ADT / 存储实现 | 元素有什么关系 / 对数据与操作作什么规范 / 如何表示这些数据与关系 |
| 线性表 / 顺序表 / 有序表 | 逻辑序列 / 顺序存储实现 / 关键字满足排序关系；不是三个同义词 |
| 单链 / 双链 / 循环链 / 静态链表 | 分别涉及链接方向、首尾关系、链接的表示方式，可以组合 |

| 栈 / 调用栈 / 堆区 / 二叉堆 | 抽象操作规则 / 调用现场的管理 / 内存分配区域 / 带堆序的完全二叉树 |
| 循环队列 / 双端队列 | 循环复用顺序空间 / 允许在哪些端操作；属于不同分类维度 |
| 满二叉树 / 完全二叉树 | 国内教材“各层全满” / “上层全满、末层靠左连续” |
| 完全二叉树 / BST / 二叉堆 | 形状要求 / 子树关键字范围要求 / 完全形状加父子大小要求 |
| 哈夫曼树 / AVL / 红黑树 | 优化带权路径长度 / 严格限制子树高度差 / 用颜色规则保证对数树高 |
| 生成树 / 最小生成树 / 最短路径 | 连通无环的覆盖结构 / 优化其总边权 / 优化起终点之间的路径代价 |
| AOV / AOE | 顶点表示活动 / 边表示活动；分别着重依赖次序与工程工期 |
| 散列存储 / 散列表 / 散列函数 | 组织与定位方法 / 具体组织结构 / 关键字到槽位或桶的映射 |
| O / 最坏情况 / ASL | 渐进上界记号 / 输入情况 / 平均比较或探测代价；不是同一分类 |
| 排序稳定性 / 性能稳定 | 相等关键字记录的次序是否保持 / 运行代价是否容易波动 |
