<a id="linear-list"></a>

## 1. 线性关系：先后次序与存放位置分开看

线性表是由同类数据元素构成的**有限序列**，可写为 `L = (a₁, a₂, …, aₙ)`，表长 `n` 可以为 0。

![线性表 A、B、C 的前后关系：B 的前驱是 A、后继是 C；位序为 1、2、3，采用零起点数组时下标为 0、1、2。](assets/ch02/01-positions.svg)

非空表中，首元素没有直接前驱，末元素没有直接后继；其他元素分别**恰有一个**直接前驱和直接后继。图中的 B 位于第 2 位，但在零起点数组中的下标是 1。

> <span style="color:#d55263;"><strong>位置 ≠ 大小</strong></span>  
> `(30, 10, 20)` 也是线性表。“有先后次序”不代表关键字已经从小到大排列。

<a id="list-adt"></a>

### 线性表 ADT：规定能做什么

ADT 规定数据对象、线性关系以及操作的效果。初始化、判空、求长度、访问、查找、插入、删除、遍历和销毁都属于操作；数组和链接是随后选择的实现。

<a id="locate"></a>

**按位访问**给一个合法位序，返回该位置的元素；**按值查找**给一个值，比较元素并确定它是否存在、位于何处。顺序表按位访问为 `O(1)`，不代表按值查找也为 `O(1)`。

<a id="sequential-list"></a>

## 2. 顺序表：把逻辑相邻变成物理相邻

顺序表用连续存储单元依次保存元素。设首地址为 `base`、每个元素占 `w` 个存储单位，位序从 1 起，则第 `i` 个元素的地址为 `base + (i−1)w`。按位访问不需要从头扫描。

<a id="capacity"></a>

**表长**是当前元素数，**容量**是可容纳的元素数。固定容量预先分配空间；动态容量可在运行时扩展，但扩容可能需要搬迁全部已有元素。动态分配得到的连续数组仍是顺序存储。

<a id="array-insert"></a>

### 插入 X：先给它腾出位置

把 X 插入 `(A, B, C)` 的第 2 位，目标是 `(A, X, B, C)`。下图假设容量为 5，无需扩容。

![顺序表插入过程：原表 A B C，先将 C 右移一格，再将 B 右移一格，最后在第二个格子写入 X，得到 A X B C。](assets/ch02/02-array-insert.svg)

<span style="color:#269c72;"><strong>为什么从后向前搬？</strong></span>  
若先把 B 写入 C 的格子，原来的 C 会在保存之前被覆盖。先搬末尾，才能逐个腾出安全的目标位置。

长度为 `n` 的表，在第 `i` 位插入需移动 `n−i+1` 个元素，其中 `1 ≤ i ≤ n+1`。图中 `n=3、i=2`，恰好移动 B、C 两个元素。

<a id="array-delete"></a>

### 删除 X：把空位补上

![顺序表删除过程：从 A X B C 中删除第二位 X，先把 B 左移，再把 C 左移，表长变为 3；原尾格不再属于有效范围。](assets/ch02/03-array-delete.svg)

删除第 `i` 位后，后缀**从前向后**左移，共移动 `n−i` 个元素，再减少表长。图中最后一个格子即使仍留有旧值，也已在有效范围之外。

**代价：**一般位置插删最坏 `O(n)`；在各合法位置等概率的常见假设下，平均也为 `O(n)`。尾部操作在无需扩容时可为 `O(1)`。

<a id="linked-list"></a>

## 3. 链表：次序记录在链接里

链表的结点包含数据域和链接域，后继由链接确定，不由“地址的下一个位置”确定。下面几个地址仅作示意，结点在图中的排列也不代表地址连续。

<a id="head-node"></a>

### 先分清入口、辅助结点和第一个元素

![带头结点的单链表：头指针 head 指向地址 0x100 的头结点；它链接到地址 0x480 的首元结点 A，再到 0x220 的 B 和 0x760 的 C，C 的 next 为空。](assets/ch02/04-linked-layout.svg)

- **头指针 `head`**：保存入口地址的变量。
- **头结点**：可选的辅助结点，通常不存有效元素；让表头插删与中间插删采用一致的处理方式。
- **首元结点**：第一个存有效元素的结点，图中是 A。

带头结点的空表仍可以有头结点，但没有首元结点。图中的链接地址只是组织方式，线性表的元素仍只有 A、B、C。

<a id="linked-insert"></a>

### 插入 X：先接住原后继，再接入新结点

仍把 X 插入 A 与 B 之间。设 `p` 已指向 A，新结点 `s` 保存 X；下图略去未参与修改的头结点。

![单链表插入三步：原状态 A 指向 B，X 尚未接入；先令 X 指向 B；再令 A 指向 X，得到 A X B C。](assets/ch02/05-linked-insert.svg)

两次修改分别是 `s.next = p.next`、`p.next = s`。第一步保存原后继 B，第二步才覆盖 A 的后继链接。

> <span style="color:#d55263;"><strong>顺序不能直接颠倒</strong></span>  
> 在没有另存原后继的情况下，先执行 `p.next = s`，再执行 `s.next = p.next`，会让 X 指向自己，并丢掉从 A 到 B 的原链接。

**代价：**已知 `p` 后，改接只需 `O(1)`；若先按位序寻找前驱，则完整插入最坏仍为 `O(n)`。这里不计内存分配器的内部开销。

<a id="linked-delete"></a>

### 删除 X：前驱绕过目标，保留后面的链

![单链表删除 X：原链为 A X B C，p 指向 A，q 指向 X；先让 A 指向 B，X 暂由 q 保存，之后再回收 X。](assets/ch02/06-linked-delete.svg)

先保存目标 `q = p.next`，再令 `p.next = q.next`，最后按所用语言的内存管理方式处理 q。**先取出后继，再回收目标**，不能回收后再读取它的链接。

已知前驱 `p` 时，摘除后继为 `O(1)`；只知道目标 X，不等于已经知道它的前驱。普通单链表通常仍需寻找前驱；双链表可以利用目标自己的前驱链接。

<a id="linked-list-kinds"></a>

### 链表分类：三个问题，分别判断

<a id="link-direction"></a>

**① 链接能沿哪个方向走？单链 / 双链**

![单链表每个结点有 next 后继链接；双链表每个结点还保存 prev 前驱链接，A 与 B 之间有两条方向相反的链接。](assets/ch02/07-directions.svg)

单链表只存后继；双链表还存前驱。双链表反向访问方便，已知目标结点时可在 `O(1)` 时间摘除，但结点多占一个链接域，插删也要维护双向链接。

<a id="circular-list"></a>

**② 最后一个结点连到哪里？非循环 / 循环**

![非循环单链表的末尾指向空；不带头结点的循环单链表中，C 的 next 回到 A。](assets/ch02/08-circular.svg)

非循环链表通常以空链接结束；循环链表的末结点回到首元结点或头结点。环形访问更方便，但遍历不能照搬“遇到空指针就结束”。本图不带头结点，回到入口 A 表示走完一圈。

<a id="static-list"></a>

**③ 链接保存什么？地址指针 / 数组游标**

![静态链表的数组下标依次为 0、1、2、3、4，A、B、C 实际分别位于下标 2、4、1，通过游标 2 到 4 到 1 到 -1 表示 A B C。](assets/ch02/09-cursors.svg)

静态链表用数组下标作为游标表示后继。上图逻辑路径是 `2 → 4 → 1 → -1`，即 A → B → C；`-1` 只是本图约定的结束标记。

即使底层数组连续，**逻辑相邻也不由相邻数组位置表示**，所以它仍是链式实现。代价是需要游标字段及空闲位置管理，不能直接用逻辑位序当数组下标。

<span style="color:#4b8ee8;"><strong>分类可以组合。</strong></span>  
例如“双向循环链表”同时回答了方向和首尾连接两个问题。“静态链表”与“静态分配”也不是同一个概念：前者说明链接怎样表示，后者说明容量怎样分配。

<a id="build-list"></a>

### 建表：头插逆序，尾插保序

按 A、B、C 的顺序读入，每次头插得到 `A`、`B → A`、`C → B → A`；每次尾插得到 `A`、`A → B`、`A → B → C`。

头插通常逆置输入次序。尾插若维护尾指针，每次接入可为 `O(1)`，整次建表为 `O(n)`；若每次从头寻找尾部，则可能累积为 `O(n²)`。

<a id="comparison"></a>

## 4. 操作代价：定位 + 修改，合起来比较

下面采用普通无序线性表，不含扩容和内存分配的额外开销。`n` 为当前表长。

| 操作与前提 | 顺序表 | 单链表 |
|---|---|---|
| 按位访问第 i 个元素 | `O(1)`，算地址 | 最坏 `O(n)`，沿链接 |
| 按值顺序查找 | 最坏 `O(n)` | 最坏 `O(n)` |
| 已定位插入处；链表已知前驱 | 最坏 `O(n)`，移动后缀 | `O(1)`，修改链接 |
| 已定位删除处；链表已知前驱 | 最坏 `O(n)`，填补空位 | `O(1)`，绕过目标 |
| 已知目标位置；单链表尚未找到前驱 | 已知下标仍要移动后缀 | 只有目标结点时仍需寻找前驱，通常最坏 `O(n)` |
| 空间特点 | 容量可能留空；一般不需逐元素链接 | 每个结点带链接；结点可分散存放 |

**经常按位置访问**，顺序表的优势明显。**已经持有前驱、经常在附近插删**，链表能省掉元素搬移。仅凭“插删多”不能决定选链表，还要看定位、容量和空间要求。

<a id="boundaries"></a>

### 三个容易混淆的边界

- **线性表 / 顺序表 / 有序表**：逻辑序列 / 连续存储实现 / 关键字满足大小次序。
- **按位访问 / 按值查找**：已知位置取元素 / 比较关键字找目标。
- **修改链接 O(1) / 整次任务 O(1)**：前者可能成立，后者还要计入寻找位置的过程。
