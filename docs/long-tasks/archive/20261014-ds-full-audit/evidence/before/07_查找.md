# 第7章 查找

> **本章要解决的问题：** 在什么数据组织和约束下，怎样定位目标记录，并兼顾查找与更新代价？

<span style="color:#2563EB"><strong>一句话主线：</strong></span>
查找目标 → 数据组织方式 → 查找方法 → 评价比较次数、树高、装填因子或外存块访问。

[返回全书总览](00_全书总览.md)

## 先看结论

- <span style="color:#2563EB"><strong>必须掌握：</strong></span>查找表保存记录，关键字用于识别或比较记录，ASL 衡量平均比较/探测代价。
- <span style="color:#DC2626"><strong>必须掌握：</strong></span>折半查找不仅要求关键字有序，还要求支持快速随机访问。
- <span style="color:#16A34A"><strong>必须掌握：</strong></span>普通 BST 的效率取决于树高；AVL、红黑树通过不同约束把高度控制在对数级。
- <span style="color:#DC2626"><strong>必须掌握：</strong></span>散列查找必须处理冲突；平均 `O(1)` 依赖散列函数和装填因子等条件，最坏仍可退化。

## 知识主线

查找不是一种固定算法，而是一个任务。先问：

1. 数据是否有序？
2. 是否需要频繁插入、删除？
3. 是等值查找还是范围查找？
4. 数据在内存还是外存？
5. 代价主要来自比较次数、树高、探测次数还是块访问？

<a id="search-basics"></a>
## 查找基本概念

- **查找表：** 供查找的记录集合。
- **记录：** 查找表中的一个数据单位。
- **关键字：** 用于识别或比较记录的字段。
- **查找成功：** 找到满足条件的记录。
- **查找失败：** 确认目标不在表中。
- **ASL：** 平均查找长度，按各情况概率加权的比较或探测次数。

成功查找和失败查找的 ASL 通常要分别计算。不能把“平均”理解成简单地取最好和最坏的算术平均。

<a id="linear-search"></a>
## 线性查找

### 顺序查找

从表的一端开始逐项比较，直到找到目标或确认查找失败。

- 不要求表有序；
- 顺序表、链表都可使用；
- 最坏时间 `O(n)`；
- 若成功概率和访问频率不均等，记录次序会影响 ASL。

<a id="binary-search"></a>
### 折半查找

在有序表中比较中间元素，每次保留可能包含目标的一半区间。

前提：

- 关键字有序；
- 能按位置快速访问中间元素。

因此，典型顺序表适合折半查找，普通链表不适合直接做高效折半，因为找中间结点本身不是 `O(1)`。

迭代实现时间为 `O(log n)`，辅助空间通常为 `O(1)`。

### 分块查找

把数据分成若干块：

- 块间按关键字有序；
- 块内可以无序；
- 先查索引确定可能的块，再在块内顺序查找。

若有 `b` 个块、每块约 `s` 条记录，索引顺序查找常近似为 `O(b+s)`；索引折半后可近似为 `O(log b+s)`。

<a id="binary-search-tree"></a>
## 二叉查找树

BST 的关键字满足：

- 左子树所有关键字小于根；
- 右子树所有关键字大于根；
- 左右子树也分别满足同样条件。

本文按关键字互异说明；若允许重复关键字，必须额外规定重复值放在哪一侧。

### 普通 BST

查找、插入和删除都沿关键字比较结果向下走，基本代价为 `O(h)`，其中 `h` 是树高。

- 平衡形状时，`h` 接近 `log n`；
- 按有序序列插入时，可能退化成链，`h = O(n)`；
- 删除双孩子结点时，常用中序前驱或后继替代，再删除替代结点。

### AVL 树

AVL 要求每个结点左右子树高度差的绝对值不超过 1。插入或删除后，通过旋转恢复平衡：

- LL：右旋；
- RR：左旋；
- LR：先左旋后右旋；
- RL：先右旋后左旋。

AVL 保持中序序列有序，查找、插入、删除最坏通常为 `O(log n)`。

### 红黑树

红黑树用颜色规则放宽严格高度平衡：

- 根和外部 NIL 叶按约定为黑；
- 红结点不能有红孩子；
- 从同一结点到各后代 NIL 的黑结点数相同；
- 插入、删除通过变色和旋转维护规则。

红黑树不要求每个结点左右子树高度差都不超过 1，但树高仍保持 `O(log n)`。

<a id="multiway-tree"></a>
## 多路查找树

### B 树

B 树的一个结点可以有多个孩子和多个有序关键字。分裂、借关键字、合并等操作用于维持结点占用限制，所有叶结点位于同一层。

若采用“`m` 表示最多孩子数”的阶数约定：

- 非根内部结点至少有 `ceil(m/2)` 个孩子；
- 非叶根至少有 2 个孩子；
- `k` 个孩子对应 `k-1` 个关键字。

不同教材对“阶”的定义可能不同，做题前必须确认约定。

### B+ 树

- 内部结点主要负责导航；
- 记录集中在叶层；
- 叶结点按关键字顺序连接；
- 适合外存索引和范围查询。

多路结构降低树高，因而可以减少外存块访问；但插入、删除要维护分裂、借位和合并。

<a id="hash-search"></a>
## 散列查找

散列函数 `H(key)` 把关键字映射到槽位或桶。不同关键字映射到同一位置时发生冲突。

### 冲突处理

- **开放定址：** 按探测序列在表内继续寻找位置。
- **链地址：** 将同一桶中的记录用链表等结构组织。

装填因子可写为：

`α = 记录数 / 槽位数`

开放定址通常要求装填因子低于 1；链地址可以允许多个记录挂在同一桶，但冲突链过长会降低效率。

开放定址删除时通常不能简单清空槽位，否则可能截断后续记录的探测路径，需使用删除标记或重组织。

## 重要方法比较

| 方法 | 主要前提 | 适合的访问方式 | 典型代价 | 主要限制 |
|---|---|---|---|---|
| 顺序查找 | 不要求有序 | 顺序表或链表 | 最坏 `O(n)` | 数据大时比较多 |
| 折半查找 | 有序 + 快速随机访问 | 典型顺序表 | `O(log n)` | 插入删除维护有序性有代价 |
| 分块查找 | 块间有序，块内可无序 | 索引 + 块内查找 | 取决于块数和块长 | 需要额外索引 |
| 普通 BST | 关键字满足左右范围关系 | 动态插删 | `O(h)` | 可能退化为 `O(n)` |
| AVL / 红黑树 | 维护平衡规则 | 动态查找与更新 | 基本操作 `O(log n)` | 更新要旋转或调整 |
| B / B+ 树 | 多路有序结点 | 外存、范围访问 | 代价主要看树高和块访问 | 维护结点占用较复杂 |
| 散列表 | 散列函数和冲突处理 | 等值查找 | 条件合适时平均 `O(1)` | 不擅长有序遍历和范围查找 |

<a id="asl"></a>
## 性质与评价

- `ASL = Σ（情况概率 × 对应比较/探测次数）`；
- 普通 BST 查找、插入、删除为 `O(h)`，`h` 可能退化到 `n`；
- AVL 和红黑树把树高控制在 `O(log n)`；
- B/B+ 树的主要代价通常与树高和外存块访问有关，不能只看结点内比较次数；
- 良好散列且装填受控时，平均查找可达 `O(1)`，但最坏情况仍可能为 `O(n)`。

<a id="boundaries"></a>
## 易错与边界

- 有序表是关键字有序，不等于顺序存储；链表也可以逻辑有序。
- 折半查找的前提是“有序 + 快速随机访问”，缺一不可。
- AVL 是严格平衡 BST；红黑树是较宽松的平衡 BST，不要混写平衡条件。
- B/B+ 树是树形查找结构，“外存”是常见应用场景，不是另一种逻辑结构。
- 散列地址通常是表内槽位或桶号，不是任意硬件物理地址。
- 查找的目标是定位；排序的目标是重排记录，二者不要混为同一任务。
