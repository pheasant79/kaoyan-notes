# 第2章 线性表

> **本章要解决的问题：** 怎样表示一条有先后次序的序列，并完成访问、插入和删除？

<span style="color:#2563EB"><strong>一句话主线：</strong></span>
线性关系 → 线性表 ADT → 顺序表/链表 → 基本操作 → 定位与修改的代价比较。

[返回全书总览](00_全书总览.md)

## 先看结论

- <span style="color:#2563EB"><strong>必须掌握：</strong></span>线性表是逻辑结构；顺序表和链表是存储实现。
- <span style="color:#2563EB"><strong>必须掌握：</strong></span>顺序表擅长按位访问，链表擅长在已知位置或前驱后调整链接。
- <span style="color:#DC2626"><strong>必须掌握：</strong></span>“插入/删除是 `O(1)`”必须说明已经找到位置或前驱；否则定位成本仍可能是 `O(n)`。
- <span style="color:#2563EB"><strong>必须掌握：</strong></span>单链、双链、循环链、静态链表来自不同分类维度，可以组合，不是四选一。

## 知识主线

线性表的分析顺序：

1. 先确定一对一的前驱—后继关系；
2. 再选择连续存储或链接存储；
3. 最后比较不同操作的“定位 + 修改”总代价。

<a id="linear-list"></a>
## 线性表是什么

线性表是由同类数据元素组成的有限序列：

`L = (a₁, a₂, …, aₙ)`

- `n` 是表长，允许 `n = 0`；
- 元素有明确的先后位置；
- 除首元素外，每个元素至多有一个直接前驱；
- 除末元素外，每个元素至多有一个直接后继。

“有顺序”只表示逻辑上的先后关系，**不表示关键字已经按大小排序**。

<span style="color:#DC2626"><strong>易错：</strong></span>
位序是逻辑位置；数组下标是具体实现中的编号。教材可能从 1 开始描述位序，而程序下标通常从 0 开始。

<a id="sequential-list"></a>
## 顺序表

顺序表用一段连续存储空间保存线性表元素，地址可由首地址和偏移量计算。

### 主要特点

- 按位访问通常为 `O(1)`；
- 物理相邻关系直接体现逻辑相邻关系；
- 插入和删除中间元素时，通常需要移动后缀；
- 扩容时可能申请新空间并搬迁已有元素。

### 基本操作

- **插入第 `i` 位：** 从后向前移动 `n-i+1` 个元素，再写入新元素。
- **删除第 `i` 位：** 删除目标后，把后面的 `n-i` 个元素向前填补。
- **尾部插入：** 在无需扩容时可为 `O(1)`。

<a id="linked-list"></a>
## 链表

链表用结点保存数据，并通过链接记录后继或前驱关系。结点不要求在物理地址上连续。

### 链表分类

<a id="linked-list-kinds"></a>

- **按链接方向：**
  - 单链表：只有后继链接；
  - 双链表：同时保存前驱和后继链接。
- **按首尾连接：**
  - 非循环链表：最后一个结点通常指向空；
  - 循环链表：最后一个结点链接回首结点或头结点。
- **按链接表示：**
  - 地址指针链表：链接保存结点地址；
  - 静态链表：用数组下标或游标表示后继。

这些维度可以组合。例如，双向循环链表同时具备“双链”和“循环”两种特征。

### 链表操作

- **按位访问：** 从入口沿链接逐结点寻找，通常为 `O(n)`。
- **单链表插入：** 先让新结点指向原后继，再让前驱指向新结点。
- **单链表删除：** 让前驱跳过目标结点；需要时回收目标空间。
- **双链表删除：** 若已知目标结点，可利用前驱和后继链接直接摘除。

<span style="color:#DC2626"><strong>关键条件：</strong></span>
已知“待删结点”与已知“待删结点的前驱”不是一回事。单链表只知道目标结点时，仍可能需要先遍历寻找前驱。

<a id="head-node"></a>
## 头指针与头结点

- **头指针：** 保存链表入口地址的指针变量。
- **头结点：** 放在首元结点之前的辅助结点，可以不保存有效数据。
- **首元结点：** 链表中第一个真正存放有效元素的结点。

头结点的主要作用是统一处理“在表头插入或删除”的边界情况；它不是线性表必须拥有的逻辑元素。

## 建表方式

- **头插法：** 新结点始终插到表头，输入次序通常会被逆置。
- **尾插法：** 新结点接到表尾，若维护尾指针，可以保留输入次序并避免每次扫描到末尾。

## 重要方法比较

| 操作或需求 | 顺序表 | 链表 |
|---|---|---|
| 按位访问 | `O(1)`，地址可计算 | 通常 `O(n)`，需沿链接查找 |
| 按值查找 | 无序时最坏 `O(n)` | 无序时最坏 `O(n)` |
| 已知位置插入/删除 | 通常要移动元素，常为 `O(n)` | 修改链接可为 `O(1)` |
| 中间频繁修改 | 可能反复移动 | 修改链接更灵活 |
| 空间利用 | 连续空间，扩容可能搬迁 | 结点带链接，额外空间较多 |
| 适合场景 | 查询多、位置访问多 | 定位后修改多、容量变化频繁 |

<span style="color:#DC2626"><strong>选择原则：</strong></span>
不能只说“插删多就选链表”。完整任务应计算“定位成本 + 修改成本”，还要看是否需要随机访问、是否能接受额外链接空间。

<a id="boundaries"></a>
## 易错与边界

- 顺序表不是“已经排好序的表”；“顺序”只指连续存储或线性次序，具体要看语境。
- 动态分配连续数组仍然是顺序存储，不会因为运行时申请空间就变成链式存储。
- 静态链表底层可能使用连续数组，但逻辑关系靠游标表示，因此仍属于链式实现。
- 循环链表的结束条件不能照搬“遇到空指针就停止”。
- 头指针是入口管理方式，头结点是可选辅助结点，二者不是同一个概念。
- 有序表上的折半查找见[第7章](07_查找.md#binary-search)；栈和队列是线性表的受限操作形式，见[第3章](03_栈队列数组.md)。
